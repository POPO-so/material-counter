# WO-0014/0015 isolated Gray8 DMA replay path

The original WO-0014 RGB packet, RTL, simulation reports and source manifests remain historical evidence. ADR-0004 freezes the WO-0015 Gray8 packet as the active Interface A baseline. The current `axis_dma_image_pipeline.v` source implements that Gray8 path; the old `axis_dma_rgb_adapter.v` remains for historical comparison and is not in the current WO-0015 Gray8 build. The 2026-10-27 BIT/HWH package passed offline build and implementation checks, but has not been downloaded to or accepted on the board.

## Frozen Gray8 packet ABI

All 32-bit words use little-endian DDR byte order. Header and footer beats use `TKEEP=4'hf`; `TLAST` is asserted only on the fourth footer word.

| Region | Contents |
|---|---|
| Header | `0x574f3134`, `(HEIGHT<<16)|WIDTH`, `WIDTH*HEIGHT`, `frame_id` |
| Payload | Row-major Gray8 pixels, four bytes per 32-bit word, byte 0 first |
| Footer | `0x454e4434`, `frame_id`, Gray8 payload byte sum modulo 2³², `0xc0dec014` |

For 320×240, the payload is 76,800 bytes and the complete packet is 76,832 bytes / 19,208 input beats. Each input beat produces four 8-bit pixels in sequence. Output `TUSER[0]` marks the first pixel and output `TLAST` marks each row end. The adapter holds each output byte and its markers stable while downstream `TREADY` is low. The 76,800-byte Binary8 S2MM stream remains four pixels per 32-bit beat.

## Active Gray8 PL path

`axis_dma_gray_adapter` checks header geometry/length, `TKEEP`, packet `TLAST`, footer identity and checksum. It serializes the payload bytes to `axis_gray2binary`, which thresholds Gray8 directly to Binary8; there is no `axis_rgb2gray` instance in `axis_dma_image_pipeline.v`. `axis_binary_output_checker` observes the Binary8 output, while `axis_s2mm_frame_packer` returns it to S2MM.

The six RTL source files in `scripts/wo0015/create_s2mm_bd.tcl` are:

- `fpga/rtl/axis_gray2binary.v`
- `fpga/experimental/wo0014/axis_dma_gray_adapter.v`
- `fpga/experimental/wo0014/axis_binary_output_checker.v`
- `fpga/experimental/wo0014/axis_dma_image_pipeline.v`
- `fpga/experimental/wo0015/axis_s2mm_frame_packer.v`
- `fpga/experimental/wo0015/axis_dma_s2mm_pipeline_bd.v`

`axis_rgb2gray`, `axis_roi_crop` and `axis_morphology3x3` are absent from the current Gray8 bitstream. `axis_rgb2gray` was included in the older RGB bitstream; its absence applies to the current Gray8 baseline, not to all historical builds. ROI crop and morphology have independent module evidence, not current image-path integration.

The original RGB adapter source and old RGB vectors are preserved for historical comparison. They must not be used with the current Gray8 image pipeline. New Gray8 vectors are generated by `scripts/wo0015/prepare_vectors.py`.

## Verification boundary

The WO-0015 full-chain testbench checks the 76,832-byte MM2S packet against 76,800 Binary8 S2MM output bytes, including randomized input gaps, output backpressure, malformed-packet cases and S2MM packer guards. The 2026-10-27 package has offline Vivado implementation and XSim evidence; it has no board download or DMA acceptance. Historical board results use the older RGB BIT/HWH pair and do not establish Gray8 board behavior. A passing software replay or static formatter gate is not Vivado synthesis, XSim, bitstream, or board evidence.
