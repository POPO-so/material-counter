# WO-0014/0015 isolated Gray8 DMA replay path

The original WO-0014 RGB packet, RTL, simulation reports and source manifests remain historical evidence. The current `axis_dma_image_pipeline.v` source has been updated for the WO-0015 Gray8 ABI candidate; the old `axis_dma_rgb_adapter.v` is retained as a non-active reference module and is not in the WO-0015 source list. This candidate is not yet an approved/frozen interface.

## Gray8 packet candidate

All 32-bit words use little-endian DDR byte order. Header and footer beats use `TKEEP=4'hf`; `TLAST` is asserted only on the fourth footer word.

| Region | Contents |
|---|---|
| Header | `0x574f3134`, `(HEIGHT<<16)|WIDTH`, `WIDTH*HEIGHT`, `frame_id` |
| Payload | Row-major Gray8 pixels, four bytes per 32-bit word, byte 0 first |
| Footer | `0x454e4434`, `frame_id`, Gray8 payload byte sum modulo 2³², `0xc0dec014` |

For 320×240, the payload is 76,800 bytes and the complete packet is 76,832 bytes / 19,208 input beats. Each input beat produces four 8-bit pixels in sequence. Output `TUSER[0]` marks the first pixel and output `TLAST` marks each row end. The adapter holds each output byte and its markers stable while downstream `TREADY` is low. The 76,800-byte Binary8 S2MM stream remains four pixels per 32-bit beat.

## Active PL path

`axis_dma_gray_adapter` checks header geometry/length, `TKEEP`, packet `TLAST`, footer identity and checksum. It serializes the payload bytes to `axis_gray2binary`; there is no `axis_rgb2gray` instance in `axis_dma_image_pipeline.v`. In the WO-0015 build, `axis_s2mm_frame_packer` remains the Binary8 return stage. Morphology RTL remains outside this image path.

The original RGB adapter source and old RGB vectors are preserved for historical comparison. They must not be used with the Gray8 image pipeline candidate. New Gray8 vectors are generated by `scripts/wo0015/prepare_vectors.py`.

## Verification boundary

The WO-0015 full-chain testbench checks the 76,832-byte packet against 76,800 Binary8 output bytes, including randomized input gaps, output backpressure, malformed-packet cases and S2MM packer guards. A passing software replay or static formatter gate is not Vivado synthesis, XSim, bitstream, or board evidence.
