# JPEG AXIS Gray8 experiment notes

This directory contains an isolated PL experiment. The public top-level API is declared in `jpeg_axis_gray.h`; vendor decoder code is pinned under `vendor/` and must remain unmodified.

## Safety and protocol contract

A downstream mask acceptance decision must require JPEG `status == 0` together with valid RLE/FRG state. A JPEG wrapper status alone does not certify downstream products. Late EOI or AXIS `TLAST` errors may occur after the full grayscale image has been emitted; in that case the packet checksum must be invalid and JPEG status nonzero, so packet metadata cannot be accepted as a good frame. Header-rejected frames may produce no output. The experimental PS caller must use a timeout because rejected/no-output inputs and decoder stalls can produce no packet; arbitrary corrupt entropy recovery is not guaranteed without an external watchdog.

The wrapper accepts one 640×400 baseline 4:2:2 scan with 8-bit precision, DQT 0/1, all four 8-bit DHT 0/1 tables, and DRI=40. APP0–APP15 segments are accepted and skipped by the pinned parser; COM and unsupported markers are rejected. Header storage is bounded to 4096 bytes. The only grayscale staging memory is one 8×640 strip (5120 bytes); the vendor Huffman decoder and four-block 4:2:2 IDCT path remain unchanged.

For accepted headers the wrapper streams the entropy payload, emits 32-bit Gray8_PACKET_V1 words with all TKEEP bits set, and puts TLAST only on the final guard word. A completed frame with an input framing, EOI, or vendor decode error gets a nonzero status and deliberately incorrect trailer checksum. Header-rejected frames emit no packet and drain the input through TLAST.

Between the pinned decoder and reorder, `guard_coefficients` forwards coefficients while counting block-end tokens, up to the fixed 8000 blocks. A separate FIFO carries the decoder status/completion token after all coefficient writes have completed. The guard drains all queued coefficients before acting on completion. If fewer blocks completed, it closes an existing partial block and supplies EOB-only, zero-DCT blocks for the remaining IDCT work. Extra coefficients are drained and flagged. The guard sends a separate error-status token to the packet sink, which reads it only after all pixels; a completed packet with synthesized or excess blocks therefore has nonzero status and an invalid checksum. These fill pixels are for terminating an invalid packet, not for image recovery. No empty-stream-read override is used.

The guard depends on the pinned decoder actually returning. In the recorded midpoint `entropy-cut` C-sim failure, execution reached `mcu_reorder start`, which establishes that the preceding decoder returned before reorder ran out of coefficients. The vendor `pick_huff_data` emits `end_sos` after finite input EOF, and Huffman checks its end state, but its decode loop has no hard iteration bound; malformed entropy/table combinations can make no progress. Therefore decoder nontermination, absent input TLAST, and stalled downstream AXIS remain subject to external PS timeout/reset. No universal malformed-entropy recovery or strict RST cadence checking is claimed. Require completed JPEG status zero plus valid downstream RLE/FRG before mask acceptance.

Table storage follows the original `kernelJpegDecoderTop` partition dimensions: DHT class/id dimensions are partitioned but their 512-entry lookup dimension remains BRAM; AC/DC value/address tables use LUTRAM; start-code tables partition only dimension 2; quantization tables partition only dimension 3. The wrapper's five-process dataflow contains declarations/pragmas and process calls only, and header parsing runs before it.

The guard and table-storage revision requires fresh C-sim and C-synthesis/co-simulation evidence. Earlier normal-frame results apply to the prior source snapshot and are preserved by the separate verification harness; they do not establish this revision's RTL behavior.
