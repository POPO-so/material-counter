# 桌面 GUI 使用说明

## 启动条件

在 Windows 资源管理器中双击 `启动GUI.pyw`。启动器优先使用项目根目录的 `.venv` 中的 `pythonw.exe`；运行环境需要提供 `tkinter`、Pillow、NumPy 和 Paramiko。GUI 沿用同目录的 `网页部署.json` 读取板卡地址、端口、部署路径及 SHA-256 期望值。更换板卡或部署版本时，先确认并更新该配置，不要从板卡现有文件反向覆盖期望哈希。

真实用户部署前，需要让当前 Windows 用户的 SSH `known_hosts` 中存在并核验目标板卡的主机密钥。程序加载系统 SSH 主机密钥，并拒绝未知主机密钥；不要改成自动信任未知主机。板卡登录沿用项目默认登录方式。

## 界面和帧处理

界面提供相机、FPGA、DMA 和系统状态，显示相机预览、Binary8 二值图、会话计数和运行指标、系统事件、图像处理调试、板端资源监视，以及采集、停止、清零、相机参数标定等操作。资源监视默认关闭。

板端沿用现有软件相机处理与计数逻辑。灰度预览和计数所用二值掩膜来自同一个相机帧；桌面连接以单帧消息同时传送 320×240 `uint8` 灰度图、同帧 Binary8 掩膜和帧号、会话号、结果及配置元数据。传输使用带版本和长度字段的 MCF1 帧格式，桌面端在一条长连接上逐帧读取；板端只保留最新帧供慢客户端读取。相机输入使用板端相机采集路径，发往 GUI 的帧以原始灰度图和二值图传输，板端不对这些帧进行 JPEG 编码。

## 启动、停止和结果

启动时，GUI 通过 SSH 上传独立会话所需文件，验证部署配置中的 manifest 和 bit 哈希，再执行板端自检及相机启动检查。GUI 只管理自己创建并核对过会话 ID 的任务；不会自动接管其他会话，也不会强制停止无法确认归属的进程。

点击“停止监控”或关闭窗口时，程序会请求板端安全停止，等待采集结束、相机资源释放、标准相机参数恢复及结果写入。若停止状态无法确认，窗口会保持打开并显示原因；不会强制结束板端进程。关闭前请等待界面确认停止。

每次板端会话结果保存在独立会话目录的 `result.json`；启动日志和自检记录也保存在该目录。Windows 本地 GUI 日志位于项目根目录 `.runtime/desktop-gui.log`。

## 网络连接排查

当前网络检查中，Windows 主机 `192.168.2.98` 的有线接口可以 ping 通板卡 `192.168.2.99`；沙箱内 TCP 测试失败，而在正常权限下 `Test-NetConnection` 对 SSH 22 端口成功。沙箱 TCP 测试失败可能来自运行环境的网络限制，不能据此判断板卡离线。

连接失败时，检查有线网卡是否启用、网线和板卡电源、`网页部署.json` 中的板卡地址，以及板卡 SSH 22 端口是否可达；再确认程序是在允许访问网络的正常桌面权限下运行。不要通过关闭防火墙或降低系统安全设置来排查。

## 验证状态

隐藏窗口联调已验证 GUI 连接真实板卡、接收同帧图像、暂停恢复、调试和安全关闭。空场景的网页与桌面模式资源对照、帧验证和限制见 [板测记录](../data/results/desktop-gui-20261028/README.md)。当前没有实物目标真值，尚不能据此判定计数准确率。
