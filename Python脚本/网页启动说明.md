# 网页启动与部署配置

双击 `启动网页.pyw`，通过项目 `.venv` 启动本机桥接并打开 `http://127.0.0.1:18765/`。板卡就绪时复用预览；未就绪时执行板端部署校验、自检及相机启动。自检失败或 DMA 状态不确定时保留现场，不自动重试或强制停止。

## 更换板卡或部署版本

编辑同目录的 `网页部署.json`，无需修改 Python 源码：

| 字段 | 含义 |
| --- | --- |
| `host`、`board_port` | 板卡 IPv4 地址或主机名、预览 HTTP 端口 |
| `board_dir` | 已部署相机预览模块的目录 |
| `runtime_root` | Gray8 自检代码及 export 产物所在根目录 |
| `python`、`pynq_init` | 板端 Python 和 PYNQ 状态检查入口的绝对路径 |
| `manifest`、`bit` | 相对于 `runtime_root` 的产物路径，禁止越出根目录 |
| `manifest_sha256`、`bit_sha256` | 经确认的部署产物 SHA-256，64 位小写十六进制 |
| `legacy_preview_paths` | 可明确识别并正常停止的历史预览启动文件绝对路径列表 |

每个字段均必须存在；不接受重复、未知字段、无效端口或不规范路径。配置错误在 SSH 连接或停止服务前报出。板端在接触自检和相机前核对两份产物的实际哈希；不要通过读取板端当前哈希自动更新期望值。更换 bit 时应同步确认 manifest 与 bit 的配套关系。

每个进程使用一份配置快照。修改配置或升级启动器后，退出旧的本项目 `启动网页.pyw --bridge` 进程再重新双击；本机桥接会校验版本和配置指纹，拒绝复用旧配置。不要结束未经确认的其他 Python 进程。桥接继续使用会话内 `Local` 互斥锁及固定回环端口。

## 板端脚本与目录

`scripts/wo0016/web_preview_start.py`、`web_preview_stop.py` 是独立的板端执行代码。启动器先本地编译检查，再以完整代码和 JSON 参数通过 SSH 执行；不要求把这两个文件预先安装到板卡。SSH 主机密钥检查和现有默认登录方式保持不变。

每次启动创建独立的 `/tmp/material-web-preview.XXXXXX` 父目录，保存 `viewer.log`、`self-test.log` 和 `self-test.json`。新版相机模块通过 `web_output_name` 使用 `camera-preview-<boot-id>` 子目录；尚未更新的板端模块保留历史 `-06` 兼容命名。在网页更新后端代码并恢复图传后启用新版命名。历史 WO-0017 直接入口仍约束原实验路径，不改写其证据目录。

本机启动状态与错误日志在项目 `.runtime/` 下。配置错误、旧桥接配置不匹配和板卡连接错误分别给出原因。

## 验证

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -B -m pytest -p no:cacheprovider scripts/wo0016/test_camera_only_preview.py scripts/wo0016/test_web_launcher_deployment.py scripts/wo0016/test_web_launcher_bridge.py scripts/wo0016/test_web_launcher_browser.py scripts/wo0016/test_web_preview_workflow.py -q
```

代理测试使用真实本机回环 HTTP 连接，验证 POST 和 MJPEG；注册表、SSH、Linux `/proc`、相机和 DMA 的外部边界使用替身。它们不能代替真实板端启动验收。若 Windows 沙箱无法加载 `_ctypes`，应在能正常加载项目依赖的环境运行，不把该环境问题标记为代码失败。
