# 过线诊断快照

## 2026-11-04 密集拆分预算与回放

任务分支为 `field-v1` 增加每帧最多 2 次完整拆分、累计父框 65536 像素与 8 ms 准入预算。时间预算在两次调用之间检查，不能中断正在执行的 OpenCV 运算，因此不是硬实时保证；参数仍需板端密集录像标定。`legacy` 不启用这些准入限制。

靠近计数线和等待较久的候选优先。未解析且超预算的父团保留为拒绝候选，不假设为单件。唯一匹配父团的当前平移归一化 RLE 序列必须逐字节相同，才能在 0.15 秒重试窗口内复用已验证的单体/孔洞/分区统计；没有缓存子掩膜，形状变化、归属歧义或清零均使复用失效。等待重试超预算时，相同当前形状仍可使用既有已验统计，诊断明确记录 `deferred`，不把旧结果伪装为重新拆分。

父团在有采集时间时使用像素/秒预测，连续观测最大间隔沿用 `max_association_interval_s=0.5` 秒；寿命为 `12 * motion_timebase_s`，当前 field-v1 为 1.2 秒。没有时间戳的历史调用保留帧号行为。补计仍要求父团越线、子轨迹数量相符、已确认且唯一归属，并通过 counted_event 统一去重。

每帧快照新增 `split_stats`、`split_diagnostics`，保存完整拆分次数、成功、缓存、延后、未解析与原因。`split_ms` 现在包括局部掩膜、子块验证及失败父团孔洞分析；旧版本只包裹拆分函数，比较前后整体开销应同时使用 `rle_regions_ms`。等待未来上下文的正常快照不再单独触发 `queue_backlog`，只有真实写入队列拥塞才触发。

CPU 回放命令（不访问 PL，不启动相机）：

```powershell
python -m scripts.standalone.performance_replay --event <事件目录/event.json> --native-lib <原生库> --output <报告.json> --repeats 3 --truth <逐件标注.json>
python -m scripts.standalone.dense_benchmark --native-lib <原生库> --output <合成与静态掩膜基准.json> --repeats 20
```

`--truth` 为可选；未提供时标 `NOT_MEASURED`。标注必须针对本次单个事件窗口，格式示例：

```json
{"schema":"material-counter.truth.v1","matching_axis":"x","objects":[{"object_id":"物料001","frame_id_min":100,"frame_id_max":105,"centroid_y":120,"lateral_tolerance_px":8}]}
```

帧区间应覆盖正常计数或补计允许出现的帧，横向位置对应 y；同一件只标一次。回放列出唯一匹配、重复、漏件、无归属事件和歧义，并绑定标注 SHA-256。真值核对使用第一个 repeat（`evaluated_repeat=1`）；应同时检查各 repeat 的语义摘要是否一致。多个 `--event` 分别冷启动、分别套用同一份标注，不做跨窗口去重，因此不同窗口应分别运行并使用对应标注。输出的采集间隔来自录像原时间戳，CPU 回放耗时来自本次执行，不能将两者混作回放掉帧证据。

结果记录：[密集计数软件优化验证](../../data/results/dense-count-20261104/README.md)。100 件合成测试不代表 100 件实物准确率，Windows 耗时不代表 PYNQ-Z2 吞吐。本任务未切换现场部署。

## 2026-11-03 field-v1 粘连诊断

`field-v1` 将在父区域上限内尝试最多16个环孔种子的拆分；拆分失败但存在2–16个相互分离的有效孔心时，父区域保留为拒绝候选并独立跟踪。父团须连续确认、在线前 armed 并实际越线；之后只有数量相符、连续稳定且可唯一落在父团预测区域的子轨迹才补计。已产生过计数事件的子轨迹不会再次补计。无父团越线证据、父子关联冲突或状态超时均不猜数。

此路径使用有界状态：最多4个并发父团、每个父团最多16个子轨迹、越线后最多保留12帧。补计事件标记 `inferred_gap=true`。新快照使用 `material-counter.crossing-snapshot.v2`，每帧增加 `cluster_parent_diagnostics`，记录 `observed`、`crossed`、`recovered`、关联冲突、容量和超时状态，以及子轨迹 ID。电脑端渲染器仍兼容读取 v1 与 v2 快照。

## 2026-10-31 优化候选行为

新集成入口默认 `--counting-profile field-v1 --snapshot-storage compact`。显式选择 `--counting-profile legacy --snapshot-storage full` 可保留 v6 的算法/完整留图方式；切换运行参数仍须正常结束旧会话后启动新会话。

`field-v1` 使用实际采集时间、速度预测和同排前后顺序约束的一对一关联；纵向速度范围为 200 像素/0.1秒，严格横向范围12像素，超过0.5秒的轨迹断档拒绝关联。这里的范围不是要求每帧移动200像素。默认仅在局部组件面积大于380且不超过1200时尝试既有粘连拆分，最小子区域面积80。暂停、清零、两次确认、竖线x=320、左→右和滞回4维持既有语义。单体和双体的现场回归只能证明已覆盖样本，不能据此宣称总体准确率。

`compact` 在板端只保存同帧原始 `gray.png`、`rle.npz` 与完整JSON。同一轨迹代次/帧号共享 `frames/e代次/` 的数据；各事件目录以硬链接保持原文件名，可独立导出而无需带共享目录。共享帧只编码和写入一次，字节额度按新增文件内容计算，目录元数据不计；错误、队列丢弃、容量预留和完成标记规则不变。硬链接不可用会报告写盘错误并停用采集，不偷偷复制数据。旧版 `full` 仍保存三种PNG。

电脑端生成二值与标注图：

```powershell
.\.venv\Scripts\python.exe -m scripts.standalone.render_crossing_snapshot <event.json> <新的输出目录>
```

工具核对灰度/RLE的字节数和SHA-256，并验证重建二值图的行列投影；既可读独立复制出来的事件目录，也可回退到共享帧目录。输出不覆盖原始证据。PNG及JSON读取失败会明确拒绝，不接受未完成组。

SIGUSR1大报告现在先在主线程持采样锁复制有界状态，再由后台线程序列化/写盘，最多一个等待任务；`report_exports` 记录提交、完成、丢弃和写入错误。状态复制仍占用少量主线程CPU，且后台Python序列化可能竞争GIL，不能宣称诊断完全无开销。

以下逐项文件说明描述 v6/full 格式；旧现场快照的48像素关联和关闭拆分参数也是v6历史配置，应以新组JSON中实际保存的参数为准。

`integrated_run.py` 的快照 CLI 参数默认开启，适用于脱机 HDMI/RLE 运行入口；实际采集还要求切入诊断模式并将 SW1 拨到 ON。每个会话的报告 `session-….json` 旁会生成独立目录 `session-….crossings/`。此功能不调整阈值、跟踪规则或计数规则，也不恢复跨会话累计计数。

## 触发条件

- 同一轨迹的目标框首次接触计数线，无论是否确认、是否处于暂停或是否计数。
- 同一轨迹的质心越过计数线，包括跳过计数线、框从未接触线的情形。
- 实际计数事件，以及被暂停或防重复规则抑制的事件。
- 未取得线上游观察的新轨迹（包括关联失败后在线后重新分配的 ID）。
- 因面积或框尺寸超限被拒绝、但与计数线相交的连通区域；此类没有稳定 ID，每秒最多触发一组。

同一处理帧的多个触发合并为一组，每个目标保留独立 `track_key=轨迹代次:目标ID` 和触发类型。每组包含前两帧、触发帧、后两帧；会话刚开始时可能不足两帧前文。停止、无效包或相机恢复切换轨迹代次时，已取得的上下文会保存并说明结束原因，不拼接不同代次。

完全没有检测框的螺母无法触发目标事件；本功能不等价于连续录像。因检测碎片小于 `min_area` 而未进入候选列表的区域，只能在其他目标触发时通过完整原图和二值图回看。

## 每组文件

`event-序号-e代次-f触发帧/` 中包含：

| 文件 | 用途 |
| --- | --- |
| `frame-帧号.gray.png` | 实际送入 PL 的 640×400 原始灰度图，无叠加、无缩放 |
| `frame-帧号.binary.png` | 由该帧 PL RLE 重建的完整二值图 |
| `frame-帧号.annotated.png` | 原图叠加计数线、绿色检测框、红色被拒绝框、ID 与跟踪状态 |
| `frame-帧号.rle.npz` | 原始游程、行投影、列投影，可用 NumPy 重放分析 |
| `event.json` | 触发目标、上下文、每帧参数/状态、父团诊断及各图像、NPZ 的字节数和 SHA-256 |

`event.json` 在所有图像写入后由临时文件重命名生成，是完整组的完成标记。没有该文件的目录属于未完成组，不用于验收。

每帧 JSON 保存检测框、聚类前候选、被拒绝候选、面积、质心、全部跟踪快照、关联位移、实际/抑制事件、累计数、暂停/清零等命令、跟踪器参数、实际包内 ROI/阈值/灰度偏移/形态学/状态/时间戳，以及采集序号和单调时钟。身份字段绑定 boot/session、应用源码 SHA-256、BIT/HWH/manifest/native 摘要和相机配置。板端墙上时钟未校准，`observed_wall_time_ns` 明确标记不可信，定位顺序使用 boot/session、轨迹代次、帧号和单调时钟。

标注中的 `C/A/K/M` 分别为 `confirmed/armed/counted/missed`。`K=1` 只是内部去重标志：在线后新建的轨迹也会直接置位，因此不能把它当作“已累计 +1”的证据，必须核对 `events` 和 `total_count`。被抑制事件结合当帧 `paused`、命令和冷却参数解释。

## 有框不计数的检查顺序

1. 核对当前为运行状态、运动方向与配置一致，且目标质心到达线后的滞回边界（当前默认 x=320，方向 +1，滞回 4 像素）。框接触线并不代表质心已达到计数条件。
2. 比较连续帧的 ID、`associations` 位移、`missed`、面积和候选框。当前脱机默认相邻帧纵向步长 48、横向步长 40 像素，未使用实际经过时间放大步长；位移超限可能重新分配 ID。这是可复现路径，不能仅凭用户现象认定现场根因。
3. 查看新 ID 是否在线上游出现并取得 `armed`、是否完成连续两次确认。首次出现在线后会被防重复规则跳过。
4. 对比原图和二值图，检查两个螺母是否成为一个连通区域。当前默认 `guarded_merge=false`，采集本身不会打开拆分；拆分策略需基于现场样本单独优化。

## 存储和运行状态

原图和 RLE 只在主流程复制到有界 RAM；PNG 编码和写盘由普通后台线程完成，不持有硬件资源。默认队列最多 8 组、上下文最多 2 帧前后，同一帧的上下文在 RAM 中共享；队列满时丢弃新组并计数，不等待 SD 卡。编码仍会消耗 CPU，实际板端开销需现场观察。

每会话最多 1,000 个完整组、512 MiB 文件内容，剩余磁盘预留 256 MiB；目录元数据不计入内容限额。达到限额或发生写盘错误后停止本会话采集，计数继续；保留既有样本，避免覆盖故障证据。限额按会话生效，多个会话共用磁盘仍受剩余容量保护。写盘失败可能保留至多一个未完成组。启动目录已存在或无写权限时同样只停用采集。

运行报告及现有 SIGUSR1 导出中，`crossing_snapshots` 给出 `accepting`、`triggered/saved`、队列和存储丢弃数、写入/采集错误、最后错误、目录和写入字节数。正常停止尝试等待后台 2 秒，`snapshot_writer_drained=false` 表示仍有待写组，不能宣称全部样本已落盘。

入口参数：`--crossing-snapshots off` 关闭；`--snapshot-max-events 1000` 和 `--snapshot-max-mib 512` 调整每会话限额。开机入口沿用默认开启行为。此版本仅接入脱机集成入口，桌面 GUI 独立入口尚未接入。

## 硬件开关

- BTN1 仍切换 normal/diagnostic；它不会绕过 SW1 或 CLI 门控。
- PYNQ-Z2 的拨码开关上拨为逻辑高：SW0 在 GPIO Channel 1 bit4，SW1 在 bit5。快照采集的条件是 `--crossing-snapshots on`、诊断模式开启且 `(channel1.read() & 0x20) != 0`。
- SW1 从 ON 切到 OFF 时停止接收新观察，并 flush 尚在等待后文的组；已经进入异步写队列的文件仍可能完成写入。重新拨 ON 后只收集新开关周期内的上下文帧。
- HWH 若声明 GPIO 宽度小于 6（包括四位基线和五位 SW0 候选），报告会显示 SW1 未接入并停用快照采集；五位 SW0 候选仍可读取 SW0 bit4。BTN1、计数和四位按键逻辑仍可运行。
