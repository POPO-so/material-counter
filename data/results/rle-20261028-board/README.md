# 640×400 Gray8 / PL RLE 优化验收（2026-10-28）

已实现并在 PYNQ-Z2 上跑通 **MJPEG → PS 原尺寸灰度解码 → Gray8 DMA → PL ROI／灰度偏移／阈值／可选形态学 → RLE／投影／帧尾 → PS 原生游程连通域／跟踪计数**。普通路径不回传整帧 Binary8，不在 PS 重建整帧后做 CCL；复杂候选可以只重建局部掩膜。

这是独立运行入口 `scripts/rle/run_counter.py` 的交付，不表示桌面 GUI 已切换到 RLE，也不替代正式 Route／接口签核。代码实现提交为 `3334a84`、`dbdb32e`、`eb1804b`；运行说明见 [RLE README](../../../scripts/rle/README.md)。

## 最终结果

- **软件：118 passed in 3.42 s**，范围 `scripts/rle scripts/gray8`；见 [软件日志](../rle-20261028-validation/software-tests.txt)。不是全仓测试全绿声明。
- RTL 八组实际 640×400 黄金向量通过，含 ROI／灰度偏移、腐蚀、膨胀、空帧、128000 游程溢出、错误包头和错误 checksum。测试等待全部输入尾字消费完成，并检查输出反压稳定和完整帧尾。见 [仿真摘要](../rle-20261028-verified-sim/summary.json)。
- 综合后小尺寸功能自检通过，专门覆盖投影 RAM 双读口与奇数地址。见 [通过日志](../rle-20261028-projection-green/sim.log)。
- 最终 50 MHz 位流实现：setup **+3.366 ns**、hold **+0.036 ns**；LUT **5809 / 53200（10.92%）**、FF **4162（3.91%）**、BRAM **2.5 / 140（1.79%）**、DSP **0**。DRC／方法学无 Error 或 Critical Warning；普通 Warning 保留在报告中。
- 本轮保留的成功板测共 **989 帧处理**，其中 **87 帧**通过完整二值掩膜还原对照，**2 帧**是预期溢出且拒绝更新计数；不同软件阶段和运行模式分别记录，不能把它们混算一个 FPS。
- 最终原生库 v2 相机 **300/300 帧**完成，**20.5651 FPS**；每帧前景 **4610–4873** 像素，**470–492** 个游程，回传 **4088–4176 B**。无溢出；本轮关闭完整像素调试比对，保留包校验、投影／游程统计一致性、DMA／硬件实际长度及身份校验。见 [最终相机记录](camera-300-native-v2.json)。
- 最终状态：两个 DMA 均 `0x1002`，PL done 且不 busy，最后帧号 299，接收长度 4132 B，无残留 RLE／相机 runner；各运行均 `buffers_held=false`。见 [状态快照](final-state.json)。

**尚未达到 30 FPS，也未验证真实物料计数准确率。** 相机出现非零前景，但没有人工真值；相机记录累计计数 0，不能解释成准确或漏计结论。当前参数是原尺寸的起点，计数轴、ROI、面积和距离仍需按真实工况标定；可用 `--counter-config` 保留 X/Y 轴及已有复杂区域规则。

## PS 开销对照

最终部署软件下，同一块 ARM、同一全帧 ROI、相同合成掩膜，每例预热 3 次、测 10 次，区域结果与像素路径一致。每个样本从空跟踪器开始，排除采集、输入编码和 DMA；RLE 列包含严格包解析及完整的区域／计数调用，不能再把单独 native 计时加一次。

| 样本 | 游程／回传字节 | 像素路径 ms | RLE 解析＋区域／计数 ms |
|---|---:|---:|---:|
| 空帧 | 0 / 2208 | 7.832 | 5.234 |
| 六个带孔目标 | 192 / 2976 | 19.795 | 7.656 |
| 589 个碎片 | 2945 / 13988 | 133.599 | 132.888 |

六个带孔目标这组 PS 耗时降低约 **61.3%**；大量碎片时收益接近零。见 [最终基准](ps-benchmark-release.json)。较早基准采用当时的旧像素校验代码，已保留但不用于最终收益结论。无法从这项对照推算整机 FPS 增幅。

最终相机阶段均值：采集／灰度解码 **12.14 ms**，输入打包＋DMA＋回传解析 **25.14 ms**，PS 区域／计数 **9.52 ms**。这是当前串行入口的时间划分，不是纯 PL 运算延迟；端到端 FPS 还包括调度和记录。下一步性能工作应依据这组证据评估采集预取、流水重叠和输入／解析开销。

## 已修复的问题与限制

首次位流的回传中，奇数行／列投影为零，包校验通过而统计一致性校验拒绝。原始回传见 [故障帧](board-projection-debug.rx.bin)。通过综合后网表仿真复现，见 [失败日志](../rle-20261028-projection-red/sim-red.log)。函数内两次读取全局 RAM 的描述改为显式独立读口后，综合后与最终板端验证均通过；早期两份位流不作为验收制品。

Vivado MCP 初次启动时代理握手成功，Vivado 子进程无输出并退出 1。配置未改，后续同工具启动成功且执行 Tcl 返回 42／Vivado 2026.1，故仅确认恢复可用，未确认初次故障根因。位流构建和仿真一直使用同一 Vivado 2026.1 后端。

该链路未实现通用 FPGA CCL；PL 输出最大行游程，PS 以原生并查集合并二维连通关系。RLE 仅在未溢出时无损保留最终二值 ROI。满画面噪声可能膨胀，超限明确拒计；不能用平均 4.1 KB 取代容量和异常设计。
