# 未来被动 UART 取证操作草案

**NOT_APPROVED_DO_NOT_EXECUTE** · 本轮不枚举、不连接、不打开任何串口。

本草案约束未来审议范围，不提供设备名或执行命令。

1. 保持板卡断电未连接；离线审阅板载 Micro-USB UART 电路、适配器和 USB 供电路径，核验 RX-only、主机 TX 与 DTR/RTS/复位输出隔离、不反向供电。若板载方案无法证明满足，保持停止；不能直接把双向 Micro-USB 当成物理单向链路。
2. 用户明确批准一个固定设备身份、一轮连接/冷启动/监听的范围后，才允许独立审议的接收适配器打开该已确认设备；禁止扫描发现或自动改选设备。打开时的驱动控制线瞬态必须在硬件层被隔离，不能依赖 Python 拦截。
3. 接收适配器的实际设置须核验为 115200/8/N/1，rtscts=False、xonxoff=False、dsrdtr=False。预案建议单次 read 超时 1 秒，单块最多 4096 字节，独立监听总界限 180 秒或 16 MiB，先到即停；这些是未来审批的固定上限建议，本轮未创建真实适配器，也未设置驱动。任何设置/读取错误立即停止，禁止自动重开和重试。
4. 在另行批准的上电之前开始已隔离的 RX 监听，以捕获最早输出；不得发送按键打断 `Hit any key to stop autoboot`，不得输入登录名/密码、命令、换行、break 或控制线脉冲。未出现 FSBL 横幅只标 NOT_OBSERVED，禁止按键/重启“补采”。
5. 主机原始字节应完整保存（不可只保留 decode 后文本），附 UTC/本地起止时间、设备身份、已审阅配置、字节数、停止原因和 SHA-256；主机侧解析另存 JSON。不修改 SD、启动脚本或板端日志。身份/凭据或敏感输出需另行脱敏审阅，不能复制历史 restricted-raw/REVISION。
6. 监听结束仍不自动 SSH/B1/B2；将原始证据和解析观察交用户/Gemini 审阅后再决定。B1-coldstart 如另获批准只登记候选，B2 继续独立审批。

串口 API guard 约束经封装使用的调用；不对恶意 Python 反射或调用方原始传输句柄提供隔离。物理线路隔离和适配器验收才是零 TX 的必要边界。正常启动可能写 SD，不能把无主动 TX 等同于整卡零写入。
