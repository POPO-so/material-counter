# Full-width mixed total counting implementation plan

Goal: add an explicitly selectable full-width PS profile for 320x240 Binary8 frames and the x=160 counting line, with group-level split-fragment merge guards and directional multi-row association.

Architecture: extend the existing counter and its evidence/permit configuration; retain the legacy default and all sealed board attempts. Integrate the supplied script's guarded grouping and isotropic full-field letterbox idea rather than replacing the established event, tracking and capture interfaces. No board access, sampling, Overlay reload or physical changes. Physical 180 mm coverage and thresholds remain unmeasured, as confirmed by the operator.

Tech stack: existing Python, NumPy, OpenCV and pytest; no new dependencies.

1. Worker owns `stream_counter.py` plus a new focused test file. First fail regressions, then implement opt-in full-height ROI, guarded Union-Find and strict lateral association. Recheck current root aggregates on every union: Euclidean bbox gap <=14, reject both areas >=95, sum <=260, inclusive bbox spans <=24. Deterministic small-fragment ordering, weighted centroid and one event per observed track. Retain legacy paths and optional dropout/hysteresis safeguards. Never infer two objects from a large component.
2. Manager owns `live_calibration.py`, `run_stream_counter.py` and new integration tests. Add a reusable full-field mapping: source 640x400 -> stride-2 320x200 -> 20 black rows above/below. Validate input, preserve source-view extent, and keep outputs independent across the camera prefetch boundary. Keep the current stretch mapping for legacy mode. Record source/output/active bounds and explicitly unmeasured physical scale.
3. Add `--counting-profile full-width-mixed` (default legacy). Bind its full-height ROI, four grouping thresholds, x160, max longitudinal step48, strict lateral10, backward tolerance4, missing budget3 and disabled corridor cooldown into the actual counting configuration. Select the same mapping in camera execution and record it in capture/READY metadata. Use actual profile configuration for the HUD axis. Thresholds are output-pixel units; no type classification or automatic touching-object doubling.
4. Tests must cover independent intact near-neighbours, exact thresholds and over-boundaries, transitive-area/span chains, fragment bridges, input ordering, multiple lanes including image edges, both directions, observed gap recovery, reverse/noise/repeat safeguards and full-frame mapping/padding/prefetch ownership. Verify old defaults and existing capture/permit behavior remain consistent.
5. Review actual diff and reference-script findings. Run focused then full offline regression. Save evidence, an operator-facing profile description and the reference-file SHA-256. Reconcile main/worktree state; do not deploy or alter existing permits.

Scope notes: the supplied reference defaults to auto-counting large components as two; that heuristic is not enabled. Its 95/260/24 thresholds and 180mm physical scale are hypotheses pending measurement. Keeping source extent does not prove the lens actually covers 180mm, nor preserve every pixel when downsampling. A Y matching gate is not a proof of physical lane identity. Full-height processing cost needs later board measurement.
