# Ground Truth 实验与人工标注流程

Ground Truth 由算法输出之外的观察来源建立。优先指定一名观察员只记录实体进入/离开检测窗口；如使用录像，录像应独立于算法预览并能回看完整进入和通过过程。不要用累计计数、Track ID 或 CCL 数量反推真实实体数。可生成 PASS/FAIL 的实体记录必须包括观察员、独立证据位置、投放顺序/时间、首末可见帧、完整可见状态、完成通过状态，以及人工审核的 Track ID 映射；任一缺项保持 `NOT VERIFIED`。标注的实体首末可见帧必须落在完整回放数据范围内；计数事件帧必须落在该实体独立确认的可见帧区间内，区间外同轨迹事件按额外/错配事件处理。

## 每次实验都必须记录

- 唯一 `experiment_id`、日期/时间、操作者、带面/照明/相机位置状态。
- 采集数据集路径及其 `manifest.json` 和 `frame-records.jsonl` 哈希。
- 独立证据来源类型、文件/记录位置和审核人。
- 实际进入检测窗口的实体数；预期投放数单独记录。
- 每颗螺母独立 `entity_id`、投放顺序和投放时间。
- 首末可见帧、是否完整进入视野、是否完成通过；不确定的字段留空并把状态保持为 `NOT VERIFIED`。
- 如需 Track ID 与实体匹配，使用独立录像逐帧人工追踪，并记录审核人和证据位置。Track ID 可在一次通过中变化，人工映射可列多个 ID。若观察确认该真实实体没有获得任何 Track ID，记录 `track_ids: []`、将 `identity_reviewed` 设为 true，并在 `identity_evidence` 说明；这会按漏检 FAIL，而不是把实体身份标成未知。
- 空带记录开始/结束帧及确认该窗口内没有物料的独立证据；帧数必须与闭区间长度一致。

复制 `GROUND_TRUTH_TEMPLATE.json` 为新数据集中的 `ground-truth.json`，只填写观察所得。保持原始空模板不变。

## 实验 A：单颗独立通过

每次只放一颗 M6 螺母。等待前一颗完全通过检测区域并从独立观察记录确认后再放下一颗。每一颗使用独立实体号。若实体未完整进入画面或未完成通过，照实记录，不将试次并入“成功通过”样本。

## 实验 B：五颗间隔通过

连续放入五颗，并在检测区域前保留可观察间距。观察员或独立录像确认实际进入窗口的实体数；不要只记录“投放了五颗”。逐颗标注窗口内出现帧和通过完成情况。实体数与投放数不一致时，以窗口观察结果为准并说明原因。

## 实验 C：近距离两颗

安排两颗彼此靠近但仍可从独立视频区分的螺母。记录间距、实际可见范围、两实体交错/靠近/分离的帧号，以及用于区分身份的视觉证据。若独立来源也无法确认哪颗对应哪个轨迹，报告 `NOT VERIFIED`，不能据总数相同判为 PASS。

## 实验 D：空带回归

带面确认无物料，在相机输入与采集模式保持一致时记录完整采样区间。独立确认实际窗口实体数为 0。验收需同时检查算法有效计数事件为 0；单独查看 `total_count` 不足以说明实体级映射正确。

## 报告状态

- `PASS`：Ground Truth 确认，且每个窗口内真实实体恰好有一个有效事件，没有重复事件、漏计、轨迹跨实体合并或额外事件。
- `FAIL`：Ground Truth 足够完整，但以上任一条件不成立。
- `NOT VERIFIED`：独立窗口实体数、事件来源或人工实体/Track 映射任一项不完整。

Ground Truth 是独立的标注文件。修改算法结果不能改写这个真值文件。
