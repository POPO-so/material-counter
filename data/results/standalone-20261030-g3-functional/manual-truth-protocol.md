# G3 真实相机与真实物料人工真值协议（执行前模板）

**状态：准备协议与空白记录模板；尚未执行。G3 未放行。** 本文件不记录样本结果，也不定义准确率门槛、样本轮次或通过标准。正式验收前由 Manager 确认这些项目。不得把历史回归、模拟输入或本模板视为真实物料验收证据。

## 目的与约束

在真实相机、真实物料运行前，先固定人工判读口径和证据记录方式。人工观察者先独立记录逐物真值并封存，再核对系统输出；不得先看系统计数或事件来调整人工记录。保留原始录像和运行报告，记录文件哈希，任何更正均留痕。

本协议记录当前 RleCounter 参数：画面 `640×400`、`count_axis=y`、`direction=+1`、`line_y=200`、`hysteresis=4`、`confirm_hits=2`。这些参数说明当前系统判定上下文；人工主真值采用下述独立可观察规则，不把软件事件定义反向用于修订人工真值。

## 人工主真值判定

- 逐个可辨识物料分配稳定且唯一的人工 ID，并记录物料类别。以物料视觉中心为判读点。
- **主真值确认一次向下穿越：**该物料视觉中心在可对齐帧序列中先位于 `y < 196`，后到达 `y >= 204`，确认上往下穿越一次。记录本次穿越的进入侧最后可见帧/时间锚点和首次到达出侧的帧/时间锚点。
- **待定事件：**若中心穿越 `y=200`，但未观察到完整的 `y < 196` 至 `y >= 204` 跨越（例如停在迟滞带内、回退或录像结束），记为待定，不计入主真值通过数；记录原因和证据锚点。
- 反向穿越、遮挡、缺帧、目标首次出现时已在线内、中心不可判、物料合并/分裂或身份不确定，均单独列出并写明逐物 ID（若可分配）、帧/时间范围、处理类别和原因。遮挡或缺帧前后的同一物料若有连续录像等独立证据证明完整穿越，仍列入主真值；证据不足时列为待定，不得直接删去以提高准确率。保留全部可观察正向物理中心线穿越数与可确认主真值数两种口径；覆盖比例为后者除以前者，分母为零时写“不可计算”。反向事件另列。
- 一物多次真实完整穿越时，每次穿越有独立序号和锚点；若方向不是上往下，列为反向边界事件，不并入主真值正向穿越数。

## 证据前提与逐物匹配限制

逐物系统匹配只有在**录像可与运行帧/时间可靠对齐，且取得完整逐事件细节**时才可判定。`CountEvent` 有 `frame_id`、`track_id`、`centroid`、`inferred_gap`，但没有事件时间戳；记录中必须保存可追溯的帧对齐关系。`integrated-run` 的 `TraceBuffer` 仅保留末尾 600 帧，尽管其哈希覆盖完整运行，长运行不能只凭该缓冲逐物匹配。

若缺少可对齐录像或完整事件细节，只报告人工总数与系统汇总计数的差值/误差，并标记“不可逐物匹配”；**不得报告 TP、FP、FN**。汇总计数相同也不证明物料身份对应或无重复/漏计。

## 核对与统计口径

完成并锁定人工记录后，才将系统输出按帧锚点、track ID、中心位置和事件详情逐一核对。每个人工有效主真值穿越最多与一个系统计数事件配对，每个系统事件最多配对一个人工真值事件。记录配对依据与不确定性，不为追求匹配率而事后改变人工 ID 或真值。

- **TP：**有一对一证据支持的人工有效主真值穿越与系统事件配对。
- **FN：**人工有效主真值穿越没有对应系统事件。
- **FP：**在已证明可逐物匹配的观察区间，系统计数事件没有对应人工有效主真值穿越，也没有对应待定或边界物理事件。
- **重复/无对应事件：**同一人工穿越对应多个系统事件时，最多一个可作 TP，其余逐项记为重复；不能对应任何人工有效穿越的系统事件记为无对应事件，并按证据注明成因未知或已知。为避免歧义，实际累计数仍归入 FP，附加原因标签。
- **待定与边界：**待定事件及上述边界项单列数量、逐项原因和锚点，不混入 TP/FN；如其间出现系统事件，单列为“与待定/边界项相关、主统计未分类”，不能暗中算成 TP 或从系统总计数中扣除。正式处理规则须在验收前确定，并同时报告全部物理事件、未分类事件及主统计覆盖比例。
- **`inferred_gap`：**此类系统事件仍计入系统观测计数；必须另列事件数、ID、帧、track ID、中心位置和匹配/无法匹配状态。不得从汇总系统计数中静默扣除。
