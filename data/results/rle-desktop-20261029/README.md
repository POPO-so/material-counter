# 桌面 RLE 接入验证（2026-10-29）

旧 GUI 显示 320×240 和 LUT 5.22%，原因是此前 640×400 RLE 只在独立入口完成板测，桌面仍使用软件阈值及整帧 MaskCounter，资源明细引用旧启动自检的静态报告。此次实际接入 PL 游程链，不靠改标签模拟接入。

桌面默认读取 `Python脚本/RLE桌面部署.json`。相机 MJPEG 直接解码为 640×400 Gray8，不缩放；PL 执行 ROI、强度偏移、阈值、可选形态学、游程和投影；PS 执行原生游程区域分析、跟踪和越线。默认全帧 ROI、阈值 128、偏移 0、形态学关闭、竖线 x=320。

MCF1 v3 预览复用同帧相机 JPEG，电脑端解码成灰度，二值掩膜以 1bit 无损传输；计数输入不受显示压缩影响。没有预览订阅者时不重建整帧掩膜。保留旧 v1 接收兼容；自检及 DMA 所有权不确定时保持 FAIL_HOLD。

## 最终实板结果

原始状态、部署源码哈希和测量窗口见 [board-check.json](board-check.json)。采用真实 PYNQ-Z2 与 Qt offscreen 窗口，实际执行接收、渲染和状态文字更新；未做人工桌面视觉验收。

| 检查 | 结果 |
| --- | --- |
| 启动自检 | 3/3 完整像素对照通过，buffers_held=false |
| 最终会话 | 570 帧，invalid_frames=0，source=pl_rle |
| 正常预览 | 20.016 s 显示 293 个不同帧，14.638 FPS；结束时板端滚动处理速率 16.598 FPS |
| 调试预览 | 5.016 s 显示 75 个不同帧，14.952 FPS；结束时板端滚动处理速率 17.316 FPS |
| 同帧一致性 | 368 组显示掩膜的前景数、400 行投影、640 列投影均与 PL 元数据一致 |
| DMA 接收长度 | 2276–2352 B/帧；不等于 GUI 网络消息总长 |
| 界面数据 | (400,640) 图像、640×400 标签、pl_rle 来源、LUT 10.92% |
| 暂停恢复/停止 | 恢复帧号递增；STOPPED、buffers_held=false、相机基准恢复；停止后无本任务进程及 8080 监听 |

正常预览结束时阶段滚动均值：采集/解码 9.308 ms，包准备/DMA/解包校验 23.649 ms，区域分析与跟踪 1.326 ms，监视和预览发布 25.157 ms。DMA 阶段包含 PS 软件操作，不能当成 PL 核心延迟。界面预览 FPS 是接收线程最近 60 帧的滚动值，与真正显示的整窗口均值不同。

首次压缩预览约 10.3 FPS，复用相机 JPEG 后约 11.4–11.9 FPS。板端微测发现 Python 3.10 的 `asdict` 递归复制 1040 个投影值约 23.84 ms；同步序列化完成帧时改用浅层数据，得到最终结果。这些开发短测不构成旧 320×240 软件链与新链的公平加速比实验。

静态资源来自固定哈希位流的 [实现报告](../gray8-rle-20261028-verified-build/reports/utilization.rpt)：LUT 5809/53200（10.92%）、FF 4162/106400（3.91%）、BRAM 2.5/140（1.79%）、LUTRAM 1731/17400（9.95%）、DSP 0。它们不是实时忙碌比例。

## 软件验证与限制

隔离提交内容执行 `python -B -m pytest -p no:cacheprovider --basetemp <独立可写目录> scripts/desktop_gui scripts/rle scripts/gray8 scripts/wo0016/test_stream_counter.py scripts/wo0016/test_web_launcher_deployment.py -q`，286 passed（7.14 s）。共享工作区另有一项用户已有 GUI 状态行测试，未混入本次提交。系统临时目录曾报 PermissionError，改用项目独立测试输出目录后通过。

本次计数为 0，没有人工物料真值；投影一致不能单独证明每个像素一致。完整像素证据来自启动自检和此前 RTL/独立板测。未达到 30 FPS；面积、跟踪门限、物理速度仍需实物标定。Route 和正式接口冻结状态不变。
