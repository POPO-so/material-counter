## 0. 先把问题定义清楚：计数的三层含义

任何计数方案都必须先区分三层，否则后续所有讨论都会错位：

| 层 | 含义 | 关键问题 |
|---|---|---|
| 第一层：单帧可分辨数量 | 在一帧图像中能分离出几个目标 | 分割质量、分辨率、粘连 |
| 第二层：跨时刻物理身份 | 第 n 帧的"目标2"和第 n+1 帧的"目标2"是不是同一个物理螺母 | 关联/跟踪 |
| 第三层：可提交的通行事件 | 该物理螺母是否完成了一次"规定的正向通行" | 事件语义、去重 |

**"一个物理螺母只被计数一次"只能由第三层保证。** 第一层和第二层是第三层的必要条件，不是充分条件。每帧识别到 N 个目标就 +N，是最常见的错误实现——它统计的是"观测次数"，不是"物理件数"。

### 0.1 计数语义建议（默认业务口径）

建议默认：在一个批次内，**完成规定正向通行的物理螺母累计一次**；计数区附近抖动和短倒退后再前进不再累计。它不同于"正向越线次数"（会把抖动算多次），也不同于"正向减反向的净通量"（会把短倒退算负再补正，口径不稳定）。

该口径的成立前提：

- 物理螺母在观测范围内**身份连续**（跟踪不断链）；
- 合并/拆分可恢复（分离后能找回原成员）；
- 已计数目标短倒退**不重建新身份**；
- 物料完全离开观测范围后再次进入，**单目无法保证识别为旧物**——需机械单向约束、受控回流或外部身份信息。这是单目视觉的硬边界，见第 7 节。

## 1. 十二类实际场景 → 算法约束映射

| # | 场景 | 对计数算法的约束 | 关键失效模式 |
|---|------|------------------|--------------|
| 1 | 单个螺母正常通过 | 基线场景，所有方案都应通过 | — |
| 2 | 多个螺母同时进入视野 | 一帧多目标，需逐目标事件提交 | 帧计数（+N）错误 |
| 3 | 螺母之间距离非常近 | 关联门控要严，防串号 | ID 切换、错配 |
| 4 | 两个甚至多个螺母相互接触 | 连通域合并，区域级计数失效 | 合并后按 1 件计（漏计） |
| 5 | 螺母部分重叠 | 轮廓/孔洞信息部分丢失 | 质心漂移、面积失真 |
| 6 | 螺母旋转、倾斜或姿态变化 | 外观特征（面积/长宽比）变化大 | 面积阈值误判 |
| 7 | 抖动、停顿或短距离倒退 | 位置非单调，时间冷却失效 | 抖动重计、倒退重计 |
| 8 | 传送带速度变化 | 恒速预测失效 | 关联漂移、漏关联 |
| 9 | 计数线附近反复移动 | 单线穿越会多次触发 | 每帧触发重计 |
| 10 | 光照不均、反光、阴影、运动模糊 | 分割阈值不稳定、轮廓破碎 | 漏检、碎片误检 |
| 11 | 相邻帧目标丢失或错误匹配 | 身份断链 | 丢件漏计、换 ID 重计 |
| 12 | 多个螺母同时跨越计数线 | 需逐轨迹分别提交 | 按帧合并为 1 事件 |

这些约束不是并列的，而是有层次的：

- **场景 1–2、8、10** 主要考验**前端分割与吞吐**；
- **场景 3–6、11** 主要考验**跨帧身份保持**；
- **场景 4–5、12** 考验**单帧可分辨性与事件语义**；
- **场景 7、9** 考验**计数事件的状态机设计**（这是"只计一次"的核心战场）。

## 2. 方案头脑风暴（8 种明显差异的方案）

方案 A–H 的差异是**本质性**的：A/B/D/E 在"区域/线条"层面计数，C/F 在"轨迹身份"层面计数，G 在"局部结构"层面辅助分离，H 在"通量"层面做校验。选主方案时不能只看资源占用，要看它是否天然满足第 0 节的三层计数语义。

### 方案 A：二值化 + 形态学 + 连通域区域占用事件

**核心原理。** ROI 内自适应阈值二值化 → 形态学开闭去噪 → 连通域标记 → 每个连通域按"沿带方向的空间相位"（上游/门/下游）维护占用状态 → 区域由空到有产生"进入事件"、由有到空产生"离开事件" → 一次完整的正向占用周期计一件。

**完整计数流程。**
1. ROI 定义与背景标定（固定阈值或逐行/逐块自适应阈值）。
2. 3×3 形态学开闭（流水线实现，行缓存）。
3. 连通域标记（RLE 游程 + 8 连通并查集，PL 有界标签表或 PS 原生实现）。
4. 每区域提取面积、质心 x、沿带方向相位。
5. 区域级状态机：ABSENT → PRESENT → ABSENT。
6. 事件判定：PRESENT 且此前 ABSENT 记"进入"；ABSENT 且此前 PRESENT 记"离开"；进入与离开配对为一次占用周期。
7. 去抖：进入/离开事件需连续 K 帧确认，防反光/阴影闪烁。
8. 计数提交：一次正向占用周期（进入在上游、离开在下游）计一件。

**图像特征。** 二值 mask、面积、质心 x 坐标、连通域数量。

**跨帧。** 依赖。区域占用状态必须跨帧保持；不能每帧独立判断。

**PS/PL。** 二值化、形态学、RLE 适合 PL 流水线；连通域合并与区域状态机适合 PS（区域数量少、随机访问合并逻辑复杂）；或 PL 有界 CCL + PS 状态机。

**资源需求（估算，非实测）。** LUT/FF 低～中；BRAM 主要用于行缓存与标签表；DSP 低；DDR 在特征化后很低（只传面积/相位/状态，不传整帧）；ARM CPU 低。

**鲁棒性。**
- 速度变化：区域占用是空间事件，与速度无关，鲁棒性好。
- 粘连（场景 4）：**致命弱点**——接触的两个螺母形成一个连通域，按一个区域计一件，漏计。
- 遮挡（场景 5）：部分遮挡会改变面积，若面积阈值做判据会误判；不做面积判据则可容忍。
- 抖动（场景 7）：区域级去抖能吸收部分，但计数线附近反复进出会产生多个占用周期，需空间滞回（U/G/D）抑制。
- 反光/阴影（场景 10）：自适应阈值能缓解，阴影会造成大面积误检。

**重复计数。** 区域在计数线附近反复进出、阴影闪烁造成占用抖动、去抖 K 值不足。
**漏计数。** 接触粘连合并、完全离开 ROI 前未建立 PRESENT 状态、碎片被形态学滤除。

**实现复杂度与实时性。** 低～中。PL 流水线容易达到高帧率；PS 区域状态机开销小。适合作为前端或轻量场景主方案。

### 方案 B：质心跟踪 + 虚拟计数线

**核心原理。** 检测目标 → 计算质心 → 相邻帧最近邻关联保持 ID → 质心穿越虚拟计数线（带方向滞回带）→ 同一 ID 只提交一次。

**完整计数流程。**
1. 前端提取目标框、面积、Σx/Σy（质心由 PS 计算，避免 PL 除法）。
2. PS 维护轨迹表：每条轨迹有 ID、最近质心、速度估计、计数状态。
3. 每帧将检测与轨迹做最近邻匹配（门控：最大距离、面积差）。
4. 轨迹更新；未匹配检测开新轨迹；未匹配轨迹记丢失。
5. 计数线设空间滞回带 [x_line−Δ, x_line+Δ]。
6. 轨迹质心从滞回带外（上游侧）进入并离开（下游侧）→ 触发一次正向穿越。
7. 同一轨迹 ID 只触发一次（rising edge + counted 锁存）。

**图像特征。** 质心坐标、包围框、面积、亮度和。

**跨帧。** 强依赖。这是该方案的本质。

**PS/PL。** 前端 PL；关联与穿越判定 PS（轨迹表规模小，纯 C/C++ 足够）。

**资源需求（估算）。** 前端 LUT/FF 中；BRAM 行缓存 + 目标表；DSP 低；DDR 低（元数据小）；ARM CPU 低～中。

**鲁棒性。**
- 速度变化：恒速假设在变速下退化；用恒速或小型 Kalman 预测 + 门控可缓解，但速度突变时仍可能丢关联。
- 粘连：两个螺母形成一个检测，一个质心计一件，漏计；**不做面积拆分时无解**。
- 遮挡：部分遮挡质心漂移，可能跳线或漏线。
- 抖动：滞回带吸收计数线附近抖动；倒退时反向穿越不计。

**重复计数。** 轨迹断链后重建新 ID 再次越线（ID switch）；质心在滞回带边缘来回震荡触发多次 rising edge（需锁存）。
**漏计数。** 关联失败、合并体、遮挡丢失、速度过快时目标跨过整条滞回带未被观测。

**实现复杂度与实时性。** 低～中。计算量小，容易实时；但**单线穿越语义在密集/粘连场景下信息量不足**，适合稀疏、间距可控的场景。

### 方案 C：全局关联 + 轨迹状态机（U/G/D 三区）★ 主方案核心

**核心原理。** 不满足于"过线一次"，而是定义**上游确认区 U → 计数门 G → 下游确认区 D** 的空间状态机。轨迹必须：在 U 被多次观测确认身份 → 通过 G → 到达 D → 且从未被计数 → 才提交唯一计数事件。合并组保留成员，分离后恢复；丢失只在唯一恢复时续接。

**完整计数流程。**
1. 标定：定义 U、G、D 三个空间区域（由定位噪声和速度确定，带方向）。
2. 前端提取候选目标（PL 有界提取，见第 6 节）。
3. PS 每帧：运动预测（恒速/小型 Kalman）→ 物理门控（运动距离、横向距离、面积变化）→ 一对一匹配（匈牙利或贪心，代价见 3.1）。
4. 轨迹生命周期管理：
   - 新轨迹：多次可信观测后才确认（防噪声/反光误检）；
   - 合并：两条轨迹相遇合并为"合并组"，保留双方成员身份；
   - 分离：合并组拆开后，各成员恢复原身份与已计状态；
   - 丢失：唯一恢复时续接；歧义转异常，不强行补数。
5. 计数状态机（核心）：
   - 轨迹进入 U 且被确认 → 进入"准备"状态；
   - 通过 G → 进入"通过门"状态；
   - 到达 D → 判定为一次完整正向通行；
   - 若该轨迹从未被计数 → 提交唯一事件，置 counted 锁存。
6. 已计轨迹退休后按最大允许回退范围保留"墓碑"记录，短倒退不重建新身份。
7. 事件以会话 ID、轨迹 ID、事件序号管理；重复帧包不重复提交。

**计数条件（形式化）。**

\[
\text{count} \iff confirmed \;\land\; observed(U) \;\land\; completed(U\to G\to D) \;\land\; \neg counted \;\land\; valid
\]

**图像特征。** 质心、包围框、面积、亮度和、质量标志、运动历史（最近若干帧位置）。

**跨帧。** 强依赖。身份、合并组、墓碑都跨帧。

**PS/PL。** 前端 PL；关联、状态机、事件账本 PS（原生 C/C++；Python 做配置、UI、低频服务）。

**资源需求（估算）。** 前端 LUT/FF 中；BRAM 行缓存 + 目标/轨迹表；DSP 低；DDR 短历史与元数据（特征包 ≤12 KB/帧 @256 目标）；ARM CPU 中（需限制关联规模，见 3.1）。

**鲁棒性。**
- 速度变化：恒速/Kalman 预测 + 门控，比方案 B 强；变速剧烈时靠 U/G/D 空间语义 + 一对一关联吸收。
- 粘连：合并组保留成员，分离后恢复——**在可观测前提下**不丢身份；合并期间不按面积折算件数。
- 遮挡：部分遮挡由关联容忍；完全遮挡无法解决（见第 7 节）。
- 抖动/倒退（场景 7、9）：U/G/D 空间滞回吸收计数线附近反复移动；短倒退后前进不重计（¬counted 锁存 + 墓碑）；这是本方案相对 A/B 的核心优势。
- 多件同时越线（场景 12）：同一帧多条轨迹各自满足条件时分别提交，不按"这帧加一"。

**重复计数。** 关联歧义（一个检测匹配两条轨迹、或一条轨迹匹配两个检测）在强制一对一下被消除；ID switch 由 confirmed + 墓碑 + 合并组成员保持缓解；无依据的面积折算被禁止。
**漏计数。** 完全遮挡、不可恢复的合并、观测缺口过长导致身份断链且无法唯一恢复。

**实现复杂度与实时性。** 中～高。状态机、合并/拆分、关联都需仔细实现与测试；但计算量小（特征包），Cortex-A9 上可实时。**这是唯一天然满足"事件而非观测"语义的方案。**

### 方案 D：窄条带时空图（Time-Space Image, TSI）

**核心原理。** 只在计数线附近取一条窄带（如高 8–16 px 的水平条带），把条带内每行的前景沿时间轴展开成二维图（x 位置 × 时间）。螺母通过时在时空图中留下斜线；斜线方向代表运动方向；每个独立斜线事件计一件。

**完整计数流程。**
1. 定义窄条带（覆盖计数线，宽度由目标尺寸与横向抖动范围决定）。
2. PL 流水线：每帧计算条带内逐行前景，写入行缓存。
3. 时空累积：条带行缓存沿时间滚动，形成 x×t 平面。
4. 在时空图中检测斜线：对每个 x 列做时间方向的上升沿/下降沿检测，或对整带做方向滤波（匹配运动方向模板）。
5. 斜线事件：某 x 位置出现上升沿（进入）与下降沿（离开）配对为一次通过。
6. 去抖与方向：正向（沿带方向）斜线计数；反向斜线不计。
7. 同一物理目标在相邻 x 列会留下斜线段，需按空间连续性合并为同一事件。

**图像特征。** 窄条带内逐行/逐列二值前景、时间方向变化沿。

**跨帧。** 依赖（条带缓存 + 时间轴）。

**PS/PL。** 非常适合 PL：条带提取、行缓存、沿检测全是流水线操作，PS 只收事件。BRAM 用于条带缓存，很小。

**资源需求（估算）。** LUT/FF 低～中；BRAM 条带缓存（几十行 × 窄宽，很小）；DSP 低（方向模板匹配可用移位+比较实现）；DDR 可很低；ARM CPU 很低。

**鲁棒性。**
- 速度变化：斜线斜率随速度变化，模板需自适应或用沿检测代替固定模板；鲁棒性中等。
- 粘连（场景 4）：**同位置相接的目标在时空图中融合为一条斜线**，无法分辨件数——这是 TSI 的本质局限。
- 遮挡：条带内可见即可，部分遮挡影响小。
- 抖动/倒退：时空图中出现锯齿，方向检测可区分正反向；计数线附近反复移动会产生多个斜线事件，需与轨迹关联配合去抖。
- 多件同时越线：不同 x 位置的独立斜线分别计数，天然支持。

**重复计数。** 抖动产生锯齿被误判为多次通过；斜线段合并不充分导致同一目标多次事件。
**漏计数。** 粘连融合、速度过快时目标在条带内停留不足未形成完整斜线、窄带过窄漏掉横向偏移目标。

**实现复杂度与实时性。** 低～中。FPGA 友好，延迟小；但**粘连场景下信息量不足**，适合作为辅助手段或间距可控场景的主方案。

### 方案 E：机械分道 + 双门事件（外部条件方案）

**核心原理。** 不靠算法分辨粘连，靠机械保证"每道同时只有一件、且件与件之间有间隙"。分道后每道维护 A/B 双门占用序列：A 门被占 → B 门被占 → A 门释放 → 提交一件；方向由占用顺序判定，短倒退由双门时序吸收。

**完整计数流程。**
1. 机械分道（振动盘/漏斗/挡板/导槽），保证单道单件排队。
2. 每道两个检测门（A 在上游、B 在下游），门可用光电、电容或窄视场成像实现。
3. 门状态机：A 占用 → B 占用 → A 释放 → 计一件；
4. 方向判定：A→B 顺序为正向；B→A 顺序为反向（不计或报警）。
5. 去抖：每门占用需持续 K 个采样确认。
6. 多道并行：各道独立计数，总计数为各道之和。

**图像特征。** 几乎不需要图像特征；门占用是 0/1 事件。若用成像实现，只需门区窄视场二值。

**跨帧。** 弱依赖（门状态跨采样保持）。

**PS/PL。** 极低开销。PL 或 PS 均可，甚至独立小逻辑。

**资源需求（估算）。** LUT/FF 很低；BRAM 极少；DSP 通常无；DDR 极低；ARM CPU 很低。

**鲁棒性。**
- 速度变化：与速度无关（占用是空间事件），鲁棒。
- 粘连：**机械保证每道单件，粘连从物理上被消除**——这是本方案最大的价值。
- 遮挡：不适用（机械约束）。
- 抖动/倒退：双门时序 + 方向判定吸收短倒退。
- 多件同时越线：多道并行，天然支持。

**重复计数。** 门信号抖动、电磁干扰误触发、遮挡物停留在门区。
**漏计数。** 卡料、分道失败、门被异物遮挡、件被导槽卡住。

**实现复杂度与实时性。** 实现复杂度低（若机械已到位）；**但依赖机械改造**。实时性极好。适合作为产线最终形态或粘连严重场景的可靠方案。

### 方案 F：编码器 + 位置预测 + 视觉融合

**核心原理。** 传送带编码器提供带累计位移 S(t)。将图像中的物料位置换算到"带面世界坐标" q(t)=y(t)−S(t)（y 为图像沿带方向坐标）。无滑移时 q 近似恒定。计数与身份判定在 q 空间进行，速度变化、停顿、短倒退被编码器位移自然吸收。

**完整计数流程。**
1. 编码器脉冲 → 累计位移 S(t)，与帧时间戳对齐。
2. 建立对时预算：USB/相机时间戳需对应曝光时刻；误差 Δt 带来约 v·Δt 的位置误差。
3. 视觉检测 → 图像坐标 y(t) → 换算带面坐标 q(t)=y(t)−S(t)。
4. 在 q 空间做占用/穿越判定（等价于方案 A/B，但坐标系是带面坐标系）。
5. 速度变化、停顿、倒退：q 空间位置随带面运动，视觉只需处理滑移误差。
6. 滑移检测：q 的异常漂移提示带面打滑，触发降级或报警。

**图像特征。** 图像位置 y、面积、时间戳；编码器位移 S(t)。

**跨帧。** 依赖（对时 + 位移历史）。

**PS/PL。** 编码器接口 PL 或 PS（GPIO 计数/定时器）；融合判定 PS 或 PL 小逻辑。

**资源需求（估算）。** 相对方案 A/B 的增量很低：位移历史 FIFO（几十~几百条记录）、对时逻辑。

**鲁棒性。**
- 速度变化：**本质优势**——速度变化被编码器吸收，视觉不需要估计速度。
- 粘连：与所选视觉前端相同（F 本身不解决粘连，需配合 C/G）。
- 抖动：带面振动会造成 q 抖动，需空间滞回。
- 倒退：编码器位移回退，q 空间自然处理；比纯视觉更可靠。
- 滑移：**致命弱点**——带面打滑时 q 漂移，身份判定失效；需滑移检测与降级。

**重复计数。** 编码器丢脉冲、对时误差导致 q 跳变、滑移。
**漏计数。** 编码器断线、滑移、对时不同步。

**实现复杂度与实时性。** 增量低，但需额外硬件（编码器）与对时验证。实时性好。**作为方案 C 的增强而非替代**：编码器解决"速度与倒退"，C 解决"身份与事件语义"。

### 方案 G：中心孔/凹点辅助局部分离

**核心原理。** 螺母（尤其六角/圆螺母）在平放时有中心孔或轮廓凹点。利用孔洞/凹点作为天然"种子"，对粘连的连通域做局部距离变换或分水岭拆分，再验证拆分结果的合理性。

**完整计数流程。**
1. 对粘连连通域提取外轮廓。
2. 检测孔洞/凹点（内部背景区域、轮廓凹陷）。
3. 以孔洞/凹点为种子，做局部距离变换，取局部峰值为拆分点。
4. 分水岭或种子生长，将连通域拆为候选子区域。
5. 验证：每个子区域的面积、形状、孔数与单件标称比对。
6. 拆分结果作为多个候选目标送入方案 C 的关联与状态机。

**图像特征。** 内孔、轮廓凹点、距离变换局部峰值、局部 mask。

**跨帧。** 部分依赖（拆分结果需跨帧关联验证）。

**PS/PL。** 拆分逻辑复杂、随机访问多，适合 PS 对少量候选做局部处理；或 PL 对有界候选做局部工作区计算。

**资源需求（估算）。** 全 PL 实现时 LUT/FF 较高（距离变换、分水岭）；PS 局部处理时 DDR/CPU 增加；只处理少量候选时可控。

**鲁棒性。**
- 平放且孔可见时：有效，能拆粘连。
- 堵孔、倾斜、侧面朝向、完全遮挡：失效。
- 旋转/姿态变化（场景 6）：孔可见性变化大。

**重复计数。** 孔误检（反光点被当成孔）导致多拆；面积验证不严。
**漏计数。** 孔不可见时无法拆分，退化为按 1 件计。

**实现复杂度与实时性。** 中～高。**只处理少量复杂候选**，不做全帧分水岭。作为方案 C 的辅助拆分模块，不是主计数器。

---

### 方案 H：面积通量积分（交叉校验）

**核心原理。** 统计计数带内前景面积通量，按速度积分换算通过物料面积，除以单件标称面积估算件数。不直接做逐件去重，用作主计数器的独立校验通道。

**完整计数流程。**
1. PL 统计计数带内前景面积 A(t)（流水线累加器，几乎零额外成本）。
2. 记录带速 v(t)（编码器或视觉估计）。
3. 通量 Q = ∫A(t)·v(t)dt。
4. 估算件数 N_est = Q / A_unit（A_unit 为单件面积标定值）。
5. 与主计数器输出比较；偏差超阈值时报警或提示异常。

**图像特征。** 面积、速度、标定常数。

**跨帧。** 依赖（积分）。

**PS/PL。** PL 面积累加器；PS 做积分与比对。

**资源需求（估算）。** 极低。一个面积计数器 + 一个积分器。

**鲁棒性。**
- 速度变化：需速度测量；无编码器时用视觉估计，误差大。
- 粘连：**面积合并不影响总通量**——这正是它的价值：能发现"主计数器漏计"（粘连时主计数少计，但通量积分仍能反映通过量）。
- 遮挡：遮挡使面积低估，通量偏低。

**重复计数。** 不做主计数，无直接重复计数问题；校验阈值过松会掩盖主计数错误。
**漏计数。** 速度测量错误、标定漂移、遮挡。

**实现复杂度与实时性。** 极低。**作为监测/校验通道，不作为主计数器。**

## 4. 主方案与备选方案

### 4.1 推荐主方案：C（全局关联 + U/G/D 轨迹状态机）

**为什么是 C。**

1. **唯一天然满足"事件语义"的方案。** 计数条件是 `confirmed ∧ observed(U) ∧ completed(U→G→D) ∧ ¬counted ∧ valid`，每帧检测不直接产生计数，只有完整正向通行才产生唯一事件。
2. **对场景 7、9（抖动、停顿、倒退、计数线附近反复移动）鲁棒。** U/G/D 空间滞回吸收反复移动；¬counted 锁存 + 墓碑阻止短倒退重计。这是 A/B/D 不具备的。
3. **对场景 4、5、12（粘连、重叠、同时越线）有原则性处理。** 合并组保留成员、分离后恢复、逐轨迹分别提交；虽然完全遮挡仍不可解（见第 7 节），但在可观测前提下是信息量最充分的方案。
4. **计算量小，Cortex-A9 可实时。** 前端在 PL 有界提取，PS 只处理特征包（≤12 KB/帧 @256 目标），关联规模可限制在 32～64 目标。
5. **可增量增强。** F（编码器）解决速度变化与倒退，G（孔洞拆分）解决可拆分粘连，H（面积通量）做独立校验，三者都作为 C 的插件而非替代。

**主方案的边界。**
- 完全遮挡/叠放不可解（见第 7 节）。
- 关联歧义需强制一对一 + 异常上报，不能强行补数。
- 关联规模必须限制，不能无条件在 Cortex-A9 上做稠密全局匹配。
- 事件账本需带会话、轨迹 ID、事件序号，防止重复帧包重复提交。

### 4.2 备选方案

**第一备选：C + F（编码器融合）。** 当传送带速度变化剧烈或存在倒退时，F 把速度与倒退问题从视觉中剥离，C 专注身份与事件语义。两者互补，推荐作为主方案的增强版本。

**第二备选：D（窄条带 TSI）。** FPGA 资源最省、延迟最小；若产线间距可控（不粘连），TSI 是性价比最高的纯 PL 方案。缺点是粘连场景信息量不足。

**第三备选：E（分道双门）。** 若机械条件允许，E 从物理上消除粘连，是产线最终形态的可靠选择。它不依赖复杂视觉算法，实时性最好；代价是需要机械改造。

**辅助模块（不单独作为主计数器）：**
- G（孔洞拆分）：配合 C 处理可拆分的粘连候选，只处理少量候选。
- H（面积通量）：配合 C 做独立校验，发现漏计/异常。

**暂不作为首条开发路线：I（小型学习检测器）。** 学习特征对外观变化适应性好，但在 XC7Z020 上的训练、量化、DSP/DDR 部署成本最高，且不解决"事件语义"问题（仍需 C 做关联与去重）。若未来前端分割质量成为瓶颈，再评估。

### 4.3 主方案完整计数逻辑（伪代码级）

```
for each frame:
    features = PL_extract(gray, roi)          # 有界提取，≤256 目标
    tracks = PS_associate(features, tracks)   # 预测→门控→一对一匹配
    for each track in tracks:
        update_track_state(track, frame)     # 位置、速度、合并组、丢失计数
        if track.confirmed and not track.counted:
            if track.observed_in(U): track.state = READY
            if track.crossed(G) and track.state == READY: track.state = PASSED_G
            if track.reached(D) and track.state == PASSED_G:
                submit_event(session, track.id, seq)
                track.counted = true
                add_tombstone(track)           # 短倒退不重建身份
    handle_merges_and_splits(tracks)          # 合并组保留成员，分离恢复
    if ambiguous_association: report_anomaly()  # 不强行补数
```

## 5. 重点：如何保证一个物理螺母只被计数一次

**"每帧识别到一次就加一"的根本错误**，在于把"观测"（observation）当成了"事件"（event）。一帧图像中检测到 N 个目标，说明的是"这一帧有 N 个观测"，不是"这一帧过去了 N 个物理螺母"。同一物理螺母在 10 帧中都会被检测到，若每帧 +1，则一件计 10 次。

保证"一个物理螺母只计一次"需要五层机制，缺一不可：

### 5.1 第一层：语义层——计数事件，不是帧观测

- 计数器累加的是**事件**（event），不是**观测**（observation）。
- 事件产生的唯一条件：`confirmed ∧ observed(U) ∧ completed(U→G→D) ∧ ¬counted ∧ valid`。
- 同一帧多件分别提交（各自轨迹满足条件时各自 +1）；**绝不按"这帧有 N 个目标就 +N"**。
- 计数只在状态机到达"提交"状态时发生一次（rising edge），不是每帧触发。

### 5.2 第二层：身份层——一对一关联防止 ID 切换重计

- 相邻帧检测与轨迹做**一对一匹配**：一个检测只能匹配一条轨迹，一条轨迹只能匹配一个检测。
- 匹配代价：`C_ij = α·d_pred + β(1−IoU) + γ|log(A_j/A_i)| + δ·d_lateral`，门控通过后才参与匹配。
- **counted 锁存**：同一轨迹 ID 只提交一次事件；即使该轨迹后续再次通过 G，因 ¬counted 不成立，不重复计数。
- **ID switch 是重复计数的主要来源**：轨迹断链后重建新 ID，再次过线会重计。缓解手段：
  - confirmed 机制（新轨迹需多次可信观测才确认，防噪声误检产生假 ID）；
  - 唯一恢复（丢失轨迹只在唯一候选时续接，不轻易开新 ID）；
  - 合并组成员保持（分离后恢复原 ID 与已计状态，不产生新身份）；
  - 墓碑记录（已计轨迹退休后保留最大允许回退范围内的身份记录）。

### 5.3 第三层：空间层——U/G/D 三区滞回，不是全局时间冷却

- **不用全局固定时间冷却压制抖动**——时间冷却会压制相邻真实目标（两件间隔小于冷却时间时后一件被吞）。
- U/G/D 是**空间滞回**：上游确认区 U、计数门 G、下游确认区 D，由定位噪声和速度确定宽度。
- 轨迹必须在 U 被观测确认 → 通过 G → 到达 D，完成 `U→G→D` 才计一件。
- 计数线附近反复移动（场景 9）：只要不完整完成 `U→G→D`，就不产生事件；已计轨迹短倒退后前进，因 ¬counted 锁存不重计。
- 短倒退（场景 7）：墓碑记录保留已计身份，倒退在最大允许回退范围内不重建新身份。

### 5.4 第四层：合并/拆分层——合并组保留成员，不按面积折算

- 两条轨迹相遇 → 合并为"合并组"，保留双方成员身份。
- **合并期间不按面积折算件数**（面积折算会把一个合并体当成 N 件或 1 件，都是无依据猜测）。
- 分离后各成员恢复原身份与已计状态：已计的不再计，未计的继续等待 `U→G→D`。
- 未知新大块（新进入的合并体，无成员历史）不按面积直接认定件数；若无法恢复成员，报告异常而非强行补数。
- 部分重叠（场景 5）：由关联 + 合并组语义处理，质心/面积漂移不影响身份判定。

### 5.5 第五层：账本层——事件序号与幂等

- 事件带：会话 ID、轨迹 ID、事件序号、帧号、配置代号、内容 CRC。
- 接收端按 `(会话, 轨迹, 序号)` 去重；**重复帧包不重复提交**。
- 重启恢复：按批次账本恢复，记录最后提交事件与在途物料；**不能悄悄重计**。
- 歧义（关联多解、合并不可恢复）转异常上报，不强行补数。

### 5.6 残余边界（必须如实声明）

- **物料完全离开观测范围后再次进入**：单目无法保证识别为旧物。已计目标远离后回流，若超出墓碑最大回退范围，会作为新目标再次计数。这是单目视觉的硬边界，需机械单向约束、受控回流或外部身份信息（如 RFID、喷码）解决，不能由算法"保证"。
- **完全遮挡期间发生通行**：被遮挡的螺母身份不可观测，任何算法都无法计数。需机械分离或多视角解决。

### 5.7 验证"只计一次"的方法

- 逐物匹配输出事件，不能只比较总数：漏 3 件与重 3 件可能互相抵消。
- Precision = 正确事件 / 全部输出；Recall = 正确事件 / 全部应计物料；分别记录漏计、重计、ID 切换、方向错误、未解决歧义。
- 测试集必须包含：抖动/倒退、计数线附近反复、粘连后分离、多件同时越线、ID 切换诱导场景。
- 约 3000 次独立通行零错误，在独立同分布假设下，单侧 95% 错误率上界约 0.1%；真实工况相关，应按十二类场景分层测试，不用大量简单重复替代复杂场景。

## 6. PS/PL 分工对计数方案的影响（简述）

计数方案必须在正确的计算位置实现，否则实时性与可维护性都会失败。详细分工见 [PLPS分工.md](PLPS分工.md)，此处只给结论：

| 阶段 | 位置 | 理由 |
|------|------|------|
| 二值化、形态学、RLE/条带提取 | PL | 流水线、行缓存、无随机访问 |
| 有界连通域/特征提取 | PL（目标）或 PS（过渡） | 完整 CCL 合并有随机访问冲突；RLE+PS 并查集是过渡方案 |
| 关联、轨迹状态机、U/G/D | PS（C/C++） | 小数据、多分支、跨帧、需调试 |
| 事件账本、去重、重启恢复 | PS | 会话级状态，需持久化 |
| 局部粘连拆分（G） | PS（限少量候选） | 复杂随机访问，不能全帧做 |
| 面积通量统计（H） | PL 累加 + PS 积分 | 流水线累加器几乎零成本 |
| 编码器融合（F） | PL 脉冲计数 + PS 对时融合 | 编码器接口 PL 或 PS 均可 |
| 叠加显示 | PL | 框、线、数字走 PL 流 Overlay，低频 UI 由 PS 生成小图层 |

**关键约束：**
- 关联规模限制在 32～64 目标，按通道或邻域降低问题规模；不能无条件在 Cortex-A9 上做稠密全局匹配。
- 完整 PL CCL 需定义每行游程上限、活动标签上限、目标上限、合并服务率、缓冲深度及超限行为；它不天然等于一像素一拍。
- 若资源或时序难收敛，先保留有界 RLE + PS 原生 CCL；噪声可能使 RLE 膨胀，不能认为它总是小数据。

## 7. 单目可观测性限制与必要工程改进

**核心原则：算法只能处理可观测的信息。如果物理信息在图像中不存在，任何算法都无法恢复。** 以下场景不能仅凭单目摄像头可靠解决，必须配合机械、光学或编码器改进。

### 7.1 完全叠放/遮挡

- **可观测性限制**：一个螺母完全遮挡另一个时，图像中只存在一个连通域/一个孔洞，"两个物理件"的信息在单帧中不存在。单目无法恢复。
- **必须改进**：
  - **机械分离**：振动盘/离心盘保证单件排队；挡板/导槽约束横向位置；节距控制保证件与件间距。
  - **背光透射**：若皮带/传送面允许透射，用背光把物料变成剪影，轮廓最清晰。
  - **多视角**：两台相机从不同角度观测，三角测量恢复空间分离。
  - **其他传感器**：光电对射、电容、称重单元辅助判定通过数量。

### 7.2 接触粘连（可拆分但不稳定）

- **可观测性限制**：接触的螺母在二值图中是一个连通域，分离依赖孔洞/凹点/局部距离变换等结构信息；当孔不可见、姿态倾斜、部分遮挡时，结构信息丢失，拆分失败。
- **必须改进**：
  - **孔洞辅助（G）**：平放且孔可见时有效，作为辅助拆分。
  - **机械节距控制**：保证件与件之间最小间距，从源头避免粘连。
  - **背光**：增强轮廓与孔洞对比度。
  - **分道（E）**：粘连严重时，分道 + 双门从物理上消除粘连。

### 7.3 反光、阴影、运动模糊

- **可观测性限制**：反光造成高亮饱和，阴影造成暗区，运动模糊造成轮廓拖影；这些都会破坏分割阈值与轮廓完整性。自适应阈值只能缓解，不能消除。
- **必须改进**：
  - **光学**：背光或漫射环形光；哑光背景（不透明皮带用哑光面）；偏振片消除金属反光；遮光罩防环境光干扰。
  - **曝光**：全局快门（OV9281 具备）改善行间畸变；短曝光限制运动拖影（拖影 b=v·t_exp，曝光应满足 b≤1–2 px）。
  - **必要时频闪**：短脉冲光冻结运动。
  - **算法侧**：自适应阈值、阴影建模、形态学鲁棒性作为次级手段。

### 7.4 计数线附近反复移动与倒退

- **可观测性限制**：螺母在计数线附近来回移动时，单线穿越会产生多次事件；短倒退后前进，若身份不连续会重计。
- **必须改进**：
  - **空间滞回（U/G/D）**：软件侧吸收反复移动，见第 5 节。
  - **编码器（F）**：带面位移约束位置，倒退被编码器吸收。
  - **机械单向挡板**：物理上阻止倒退，最可靠。
  - **墓碑记录**：软件侧保留已计身份的短时回退范围。

### 7.5 倒转/回流

- **可观测性限制**：物料倒转回流时，单目无法区分"回流的旧件"与"新进入的件"；已计目标远离后再进入，无外部身份信息时必然作为新目标计数。
- **必须改进**：
  - **机械单向约束**：挡板、棘轮、单向离合器，物理上禁止回流。
  - **受控回流通道**：若有回流，走独立通道并重新识别。
  - **外部身份**：RFID、视觉码、喷码，提供物理唯一身份。
  - **净通量模式**：若无法禁止回流，明确声明系统只能做净通量统计（正向−反向），不做批次绝对计数。

### 7.6 速度变化与对时

- **可观测性限制**：USB 相机时间戳若不对应曝光时刻，误差 Δt 带来约 v·Δt 的位置误差；编码器与相机若不同步，融合结果不可信。
- **必须改进**：
  - **编码器（F）**：提供带面位移基准，吸收速度变化。
  - **硬触发**：用编码器位置触发相机曝光（若模组支持），消除对时误差。
  - **对时预算**：明确 USB 时间戳 → 曝光时刻 → 帧可用时刻的误差预算，并实测验证。
  - **滑移检测**：编码器融合需检测带面打滑，打滑时降级或报警。

### 7.7 采样不足

- **可观测性限制**：速度过快或视场过大时，每件在观测区内的帧数不足（有效观察长度 L、带速 v、每件至少 K 次观测时需 LF/v≥K），确认、方向判定、合并恢复都不可靠。
- **必须改进**：
  - 提高帧率（相机标称 MJPEG 640×400@220，但 USB2.0 带宽与持续帧率需实测）。
  - 缩小视场（提高采样率 s=px/mm）。
  - 限制带速。
  - 必要时用编码器在带面坐标系补采样。

### 7.8 改进优先级建议

| 改进 | 解决的场景 | 优先级 | 理由 |
|------|-----------|--------|------|
| 背光/漫射光/偏振/遮光罩 | 反光、阴影、模糊（7.3） | 高 | 光学改善是性价比最高的输入质量提升 |
| 短曝光/全局快门利用 | 运动模糊（7.3） | 高 | 传感器已具备，只需配置验证 |
| 机械节距控制/单向挡板 | 粘连、倒退、回流（7.1、7.4、7.5） | 高（产线最终形态） | 从物理上消除最难算法场景 |
| 编码器 | 速度变化、倒退、对时（7.6） | 中 | 与方案 C 融合，显著提升鲁棒性 |
| 孔洞辅助拆分（G） | 可拆分粘连（7.2） | 中 | 作为方案 C 辅助，限少量候选 |
| 分道双门（E） | 粘连严重场景（7.2） | 中（视产线条件） | 机械到位后可靠性最高 |
| 多视角 | 完全遮挡（7.1） | 低（成本高） | 仅当单视角无法满足时 |
| 外部身份（RFID/喷码） | 回流识别（7.5） | 低 | 仅当需要批次绝对计数且无法禁止回流时 |

## 9. 结论

1. **计数问题分三层**：单帧可分辨数量、跨时刻物理身份、可提交通行事件。"只计一次"只能由第三层保证。
2. **主方案：C（全局关联 + U/G/D 轨迹状态机）。** 它是唯一天然满足"事件语义"的方案，对抖动、倒退、计数线附近反复、粘连合并、多件同时越线有原则性处理。
3. **增强：F（编码器融合）** 解决速度变化与倒退；**G（孔洞拆分）** 辅助可拆分粘连；**H（面积通量）** 做独立校验。
4. **备选：D（TSI，FPGA 最省）、E（分道双门，机械到位后最可靠）。**
5. **"只计一次"的五层保证**：语义层（事件≠观测）、身份层（一对一关联+counted 锁存）、空间层（U/G/D 滞回≠时间冷却）、合并/拆分层（成员保持≠面积折算）、账本层（事件序号幂等）。
6. **单目硬边界**：完全遮挡、完全叠放、倒转回流、采样不足不能仅凭算法解决，必须配合机械分离、光学改善、编码器与外部身份。任何声称"算法能解决"的说法都缺乏依据。
7. **验证口径**：逐物匹配，分别统计漏计/重计/ID 切换/方向错误；不用总数掩盖错误；按十二类场景分层测试。
