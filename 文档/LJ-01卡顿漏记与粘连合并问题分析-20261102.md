## 1. 问题与代码事实

用户报告的三个现象：

1. **螺母数量超过 10 个就开始卡顿、漏记。**
2. **两个螺母粘连、重叠时，有概率合并为一个目标框。**
3. **快照机制尚未部署到板端实际验证，验证后可通过快照调试。**

代码走查确认的事实（关键行号）：

## 2. 根因分析

### 2.1 为什么超过 10 个就卡顿

PS 侧每帧固定成本 + 随目标数增长的成本：

1. **关联门控 O(tracks×detections)**：10 轨 × 10 检 = 100 次 Python 迭代；20 × 20 = 400 次。每次迭代含若干浮点运算、比较与 `edges.append`。Python 层面每帧约 0.1–1 ms 量级，随密度平方增长。
2. **guarded_merge 聚类 O(N²)**：同样随密度平方增长，且 union-find 的 `find` 在 Python 层。
3. **拆分路径**：`local_mask` 逐 run Python 循环 + `split_touching_component`（OpenCV 连通域 + 测地孔分配 + 递归）。field-v1 把拆分窗口放宽到 380–1200 后，**每个"疑似双体"候选都会走一遍完整拆分**；高密度时一帧出现多个候选，拆分总耗时可达数 ms 甚至更高。
4. **帧结果组装**：投影转 list、tracks 快照转 tuple/dict，每帧固定开销。
5. **无帧预算保护**：`region_ms`/`track_ms` 已埋点（`counter.py:127`），但没有"超预算即降级"的逻辑——拆分和聚类不会因为超时而跳过。

叠加 MJPEG 解码、DMA、显示合成后，PS 侧总耗时逼近 33 ms/帧（30 FPS 预算），表现为卡顿；卡顿又造成帧处理延迟与丢帧，反过来触发漏记（见 2.2）。

### 2.2 为什么超过 10 个就漏记

1. **确认机制在丢帧下失效（最直接）**：`streak` 仅在 `dt == 1` 时累加，`dt != 1`（丢帧、乱序、延迟）即重置为 1。高密度+卡顿时 dt≥2 频繁发生，轨迹反复达不到 `confirmed`，即使它一直被观测到也不计数。
2. **轨迹快速死亡**：`max_missing=1` 下两帧未匹配即 `finished`；卡顿时关联质量下降，死亡加速，下游重建新 ID——新 ID 若出生在计数带下游（`side >= -hysteresis`）直接 `counted=True` 被忽略（`stream_counter.py:873-880`），造成漏记；若出生在上游则重新走完整流程，造成**同一物理螺母被两个 ID 先后观测**。
3. **门控过严**：field-v1 `strict_lateral_gate=True, max_lateral_step=12` 对身份有利，但高密度+抖动时横向 12 px 门可能拒真；`max_step=200` 的速度门在变速下也会拒真。
4. **计数语义是方案 B（单线穿越）**：没有下游确认区 D。`counted` 锁存防同轨重计，但**不防 ID 切换重计**——`cooldown_frames` 默认 0，`last_suppressed_events` 机制存在但默认不启用。

### 2.3 为什么粘连/重叠有概率合并为一个框

1. **拆分是启发式，验证严格**：孔洞法需要 2–3 个**可见**孔（面积阈值、孔距 ≥10 px）；颈部法需要投影出现窄颈；两者都失败则回退单框。倾斜、部分重叠、反光遮孔都会让验证失败——这就是"有概率"的来源。
2. **面积上限**：`area > max_split_area (1200)` 的合并体永不拆分（如三件叠合、大螺母+噪声膨胀）。
3. **无合并组语义**：当前逻辑里"一个连通域 = 一个候选 = 最多计一件"。合并体未经拆分就直接进关联，被当作 1 件。方案一文档中的合并组（保留成员、分离恢复）尚未实现。
4. **guarded_merge 碎片合并**：`_cluster_components` 会把小碎片合并进邻近候选（`stream_counter.py:579-581` 对完整件有 `single_intact_area` 保护），但碎片化的重叠件可能被拼成更大的单一框。

## 3. 解决方案（按优先级）

### P0-1：先把快照闭环跑起来（当前最缺的证据）

快照机制已实现但未上板验证。建议第一个动作不是改算法，而是**用快照把现场证据拿回来**：

1. 板端启用 compact 快照（`--counting-profile field-v1 --snapshot-storage compact`），覆盖 >10 件高密度段与粘连段。
2. 拉回 Gray8 + RLE + 标注图 + 逐帧 timing（`roi_subtimings_ms` 已有 `rle_regions_ms`/`track_ms`）。
3. 用 `scripts/standalone/performance_replay.py`（冷 CPU 回放 field-v1）离线复现，逐帧对比"检测数 vs 前景通量"，定位卡顿发生在哪个阶段（拆分/聚类/关联/组装）。
4. 粘连样本：对每个合并框记录拆分尝试是否触发、哪个启发式失败、验证在哪一步失败。这决定 P1-2 的改动方向。

### P0-2：性能热点优化（解决卡顿）

1. **关联门控向量化/原生化**：门控是纯质心算术，可把 `stream_counter.py:736-798` 的循环改为 NumPy 向量化对，或下沉到 `rle_components.cpp` 同库的 C++ 函数（输入 tracks/detections 数组，输出 edges 数组）。预期 10–50× 提速，直接消掉 O(N²) Python 开销。
2. **拆分 rasterization 优化**：`local_mask` 的逐 run Python 循环改为向量化填充（按 run 的 (row, begin, end) 一次性切片赋值），或直接在 C++ 侧从 runs+labels 产出 bbox 掩码。
3. **帧预算保护**：给拆分/聚类加预算（如拆分总预算 3 ms、聚类 2 ms）；超预算时本轮跳过拆分、直接用 PL 特征包（`pl_features` 路径已存在），并在遥测中标记降级帧。**宁可这帧少拆，不可整帧超时**。
4. **拆分候选限流**：每帧最多处理 K 个候选（如 4 个，按面积最可疑优先），其余留到下一帧——合并体是慢变目标，跨帧拆分可行。
5. **投影组装降载**：`row/column_projection.tolist()` 改为按需转换（仅在快照/显示需要时），热路径保留 numpy 数组引用。
6. **PL 侧防噪声膨胀**：若快照显示 RLE runs 数量随密度爆炸（噪声碎片），优先在 PL 端加强形态学（近零成本），而不是在 PS 端过滤。

### P1-1：确认机制修复（解决高密度漏记）

1. **确认改为滑窗计数**：将 `streak`（要求连续 dt==1）改为"最近 W 次匹配中成功次数 ≥ confirm_hits"，容忍丢帧。或至少允许推断恢复的 gap（`edge_recovery`/`predicted_recovery` 已存在）不重置 streak。
2. **轨迹死亡预算提高**：`max_missing` 从 1 提到 2–3，配合 `prediction_max_missing`/`edge_max_missing` 的推断恢复，减少卡顿期误死亡。代价是 ID 切换窗口变大——用 P1-3 的去重补偿。
3. **门控调参**：以快照回放为依据调 `max_lateral_step`（12 → 14–18）与 `max_step`；变速明显时启用速度自适应门。
4. **计数带位置核查**：确认 x=320 与 ROI 覆盖真实过线位置；出生在带下游的新轨迹被忽略是语义正确，但若现场大量"入场即过线"，说明带位置或 ROI 需要重标定。

### P1-2：粘连拆分增强（解决合并框概率）

1. **增加距离变换鞍点拆分**：对合并掩码做距离变换，在两个局部峰之间的鞍点（谷值）切开。对圆螺母/六角螺母接触件比颈部投影更鲁棒，且不依赖孔可见。这是经典"接触圆分离"方法，PL/PS 都可实现。
2. **多假设打分**：孔洞法 / 颈部法 / 鞍点法并行尝试，按子区域面积合理区间、圆度/实心度打分选最优，输出置信度与所用方法（复用 `_split_origins` 记账）。
3. **面积上限自适应**：以快照实测的合并体面积分布标定 `max_split_area`；三件叠合（>1200）不强行拆分，转 P2-1 的"疑似多件"处理。
4. **拆分结果跨帧复核**：拆分出的子区域在后续帧应保持分离轨迹；若下一帧又合并，说明拆分可能错误，回退并标记。

### P2-1：合并组语义与通量校验（语义升级，对应任务一方案 C/H）

1. **"疑似多件"标记**：面积超过单件上限且无法拆分的合并体，标记为 `suspect_multi`，**不再按 1 件计数**；其计数延后到满足额外证据（后续分离出 N 个子轨迹、或通量校验支持 N 件）才提交。宁可暂缓，不可错计。
2. **面积通量交叉校验**：PL 已提供每帧 `total_fg` 与投影（`counter.py:124-126`）。统计计数带内前景通量，与主计数速率比较；偏差超阈值即报"疑似漏计（合并）"。成本极低，能直接暴露合并框导致的漏计。
3. **下游确认区 D（方案 C 的 U/G/D）**：在计数带下游加窄确认区，轨迹穿过计数带后到达 D 才提交。吸收计数线附近抖动，且为 ID 切换提供缓冲。改动集中在 `_associate_and_update` 的状态字段，前端不动。

### P2-2：机械手段（产线最终形态）

- 计数工位前加节距控制/挡板/导槽，保证件间距；粘连严重时加分道。
- 光学：背光或漫射光 + 偏振，提升孔洞与颈部可见性，直接提高拆分成功率。
- 这些对应任务一文档第 7 节的可观测性边界：**软件拆分只能处理"信息仍在图像中"的粘连；机械/光学解决"信息根本不存在"的场景。**

## 4. 建议实施顺序

| 步骤 | 内容 | 依据 |

| 1 | 板端部署快照闭环，采集高密度+粘连样本 | P0-1；当前最缺现场证据 |

## 5. 验证方法

- **离线回放**：`scripts/standalone/performance_replay.py` 冷回放 compact 证据，逐帧对比检测数与前景通量。
- **逐物匹配**：输出事件与物理真值一一匹配，分别统计漏计、重计、ID 切换、方向错误、未解决歧义；Precision/Recall 分别计算。
- **分层测试**：>10 件高密度、粘连双体、重叠、倒退、计数线附近反复，每类独立统计，不用大量简单重复替代复杂场景。
- **性能验收**：帧耗时分阶段（region/track/split/cluster/associate/assemble）记录 P50/P95，卡顿以"处理帧率 ≥ 显示帧率且无持续积压"为门槛。
