# 板端 haveged 崩溃修复（2026-11-04）

## 范围与结论

本次经用户授权修复 PYNQ-Z2 的 haveged 崩溃重启循环。仅增加一个持久 systemd drop-in 并重启 haveged；没有重启开发板、计数服务或重载 PL，没有改动应用 release、网络、SSH、账户和软件包。

- 板卡：`192.168.2.99`，ARMv7，Linux `6.6.10-xilinx-v2024.1-g3c0eca68c652`。
- 软件：haveged `1.9.14-1ubuntu1`、glibc `2.35-0ubuntu3`、systemd `249.11-0ubuntu3`。
- 本次 boot ID：`b5946644-d2cd-4f31-9e2c-a7b236865a89`。
- 计数服务 PID 全程保持 `897`，release 为 `standalone-20261103-lj01-undercount-5438e0e`。
- 部署类别：FULL 中的单个系统服务配置更新；实际仅 reload systemd 配置和 restart haveged，没有整板重启。
- 板卡时钟不准确；文档日期取开发端日期，验证使用 boot ID、进程和运行样本关联。

## 根因证据

1. 原 `/lib/systemd/system/haveged.service` 设置 `Restart=always`、`RestartUSec=100ms`。日志持续出现 `status=31/SYS` 和 `Failed with result 'core-dump'`；本轮只读观察中 `NRestarts` 从 222 增至 278。每次崩溃触发 apport，额外占用 CPU。
2. 原 unit 的系统调用白名单为 `@basic-io @file-system @io-event @network-io @signal` 加 `arch_prctl brk ioctl mprotect sysinfo`，没有 `uname`。
3. 读取现有 `/var/crash/_usr_sbin_haveged.0.crash`，按行解码 Base64、解压 gzip，并解析 ELF32 的 `NT_SIGINFO`，得到：

   ```json
   {"signal":31,"errno":0,"code":1,"call_addr":"0xb6f02a68","syscall":122,"arch":"0x40000028"}
   ```

   `code=1` 对应 `SYS_SECCOMP`；板端 `/usr/include/arm-linux-gnueabihf/asm/unistd-eabi.h` 明确 `__NR_uname = __NR_SYSCALL_BASE + 122`。这份崩溃文件为既有历史记录，日期不作为本轮时间证据；本轮相同信号的重启循环和增补后恢复共同验证了原因。
4. ARM 动态链接器调用 uname 被白名单拦截，是本次最小修复依据。上游也记录过同类 [ARM haveged SIGSYS 故障](https://github.com/jirka-h/haveged/issues/41)。ARM 调用号见 [Linux v6.6 syscall 表](https://github.com/torvalds/linux/blob/v6.6/arch/arm/tools/syscall.tbl)。

## 最小修复与复用

源文件：[haveged-arm-uname.conf](../scripts/standalone/systemd/haveged-arm-uname.conf)。板端安装路径：

```text
/etc/systemd/system/haveged.service.d/90-material-counter-arm-uname.conf
```

有效配置仅追加：

```ini
[Service]
SystemCallFilter=uname
```

重复的 allowlist 声明会合并，空值才重置；见 [systemd 249 官方手册](https://www.freedesktop.org/software/systemd/man/249/systemd.exec.html#SystemCallFilter=)。原有 syscall 限制、能力限制、私有设备/网络、文件系统保护等保持生效，没有关闭 seccomp 或 apport。

将源配置传到目标板后，以该文件实际路径替换下述 `<uploaded-config>`，可复用安装步骤：

```sh
sudo install -D -m 0644 <uploaded-config> /etc/systemd/system/haveged.service.d/90-material-counter-arm-uname.conf
sudo systemctl daemon-reload
sudo systemctl restart haveged.service
systemctl show haveged.service -p MainPID -p ActiveState -p SubState -p NRestarts
```

首次安装时确认目标文件不存在，以独占创建方式写入；未覆盖已有配置。板端文件与仓库源文件 SHA-256 一致：`8e831d8a681c24040eb26304001e7169222893adfc523ce8939e61a9344d8af1`。

## 回退

```sh

sudo systemctl daemon-reload
sudo systemctl restart haveged.service
```

回退将恢复已知的 SIGSYS 风险，仅在需要撤销本补丁时使用。保留原厂 unit 和既有崩溃记录以便追查。
