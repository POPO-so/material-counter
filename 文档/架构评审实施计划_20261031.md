# 下一代计数架构实施计划（评审推荐方案落地）

- 日期：2026-10-31（北京时间）
- 分支：`nextgen-architecture`，基线 `c248244`（自 `LJ-01` 创建）
- 依据：[架构评审](PYNQ-Z2螺母视觉计数系统_问题与架构评审_20261031.md)、[演进对比](现有仓库演进与新仓重建对比_20261031.md)
- 性质：实施计划与验收口径。不冻结 Route、接口协议或正式验收签字；Route/接口变更需按项目规则另行决策。

## 1. 关键决策（继承对比文档结论）

1. **同仓演进，不新建仓库。** 现仓库已解决 USB 采集、DMA/overlay 适配、RLE 与 PS 原生 CCL、HDMI、所有权与故障收尾等资产；新仓库不会自动消除相机吞吐、物理可观测性、身份去重与接口决策问题。
2. **独立分支隔离，候选入口与稳定接口并存。** 在 `nextgen-architecture` 上建立模块边界与候选入口，与现有入口长期对照；验证后按项目规则合并。
3. **逐步替换，先稳定语义再下沉。** 不一次性重写；先用当前 RLE＋PS 原生 CCL 喂新 tracker，再按实测瓶颈决定 PL CCL、编码器、PL Overlay 是否开工。
4. **高风险模块分别验证，不并行铺开。** PL 完整 CCL、全量 C++ 跟踪、PL Overlay、编码器各自是分阶段工作，不是首个可靠计数版本的必然前置条件。

## 2. 目标架构摘要（评审文档推荐，未冻结）

- 算法主线：有界 PL 预处理（ROI/校正/滤波/分割/形态学）→ PL 有界游程/标签合并（目标特征）→ 特征包 → PS 关联与状态机（U/G/D 越线、确认、去重、事件幂等、身份保持）。
- 过渡路线：当前 `scripts/rle`（PL RLE 流水线＋PS 原生 CCL）作为首版检测前端，先接入新 tracker，不同时更换全部前端。
- 特征 ABI 建议（设计目标，非当前协议冻结）：64 B 帧头＋每目标 48 B＋4 B 尾；固定小端、偏移、对齐与版本；容量保护（每行游程上限、标签/目标上限、缓冲深度、超限行为）。
- 显示：高频几何（框/线/ID/数字）走 PL Overlay；低频面板/中文 UI 由 PS 小图层＋PL 合成。
- 监控：PL 计数器＋PS 采样；严格区分综合静态资源、运行期可测指标、Linux 可读指标、需硬件计数器的指标。

## 3. 分阶段实施

| 阶段 | 目标 | 关键交付 | 验收 | 风险/边界 |
|---|---|---|---|---|
| P1 基线 | 保存可追溯基线 | 候选入口清单、位流/配置、证据版本边界 | 盘点经 Worker 只读核对，Manager 复核 | 历史证据不可重写 |
| P2 输入与真值 | 核实相机能力与整链耗时 | 模式/曝光/持续 FPS/时间戳语义实测；含粘连、倒退、停顿、丢帧的真值集 | 每段耗时分位、真值逐物标注 | 无独立真值不能算准确率 |
| P3 稳定接口＋新 tracker | 抽出检测结果/事件接口 | 特征/事件 ABI、新 tracker 入口，由当前 RLE＋PS CCL 喂入 | 同输入新旧对照（事件序列一致） | 行为等价不等于性能等价 |
| P4 U/G/D 与去重 | 越线状态机与身份保持 | 事件幂等、丢失恢复、已计数墓碑、同排顺序 | 逐物事件匹配；重复/缺包/反压负例 | 不凭语言选择推定提速 |
| P5 PL CCL 下沉（按实测） | 按瓶颈决定 | PL 标签合并、目标表、帧包、容量保护、局部分离数据入口 | 黄金等价、吞吐、资源、最坏合并 | 高复杂模块，分阶段验证 |
| P6 编码器 | 变速/倒退需求 | 电气、对时、滑移、采样/计数 | 编码器与视觉对时预算 | 软件时间戳不能冒充编码器 |
| P7 显示与监控 | 显示隔离 | HDMI 同帧配对、计数隔离；按证据加 PL Overlay | 显示开关不改变计数事件 | 不抢在准确性与输入瓶颈前 |
| P8 汇总与验收 | 遥测、候选包、文档 | 遥测汇总、候选包刷新、受影响范围验收 | 按项目机制签字/冻结 | 重新验收修改所影响范围 |

上表是实施顺序，不是机械次数；P5–P7 按实测证据决定是否开工。

## 4. 委派规则

- Manager 主导：架构、接口、参数决策、集成、验收、跨模块修改、高风险操作。
- `luna_explorer`（只读）：源码/日志检索与信息提取，供 Manager 复核。
- `luna_worker`（低风险执行）：明确范围的本地脚本、测试、回放工具、文档整理；禁止二次委派、修改范围外文件、操作板卡。
- Worker 返回 changed files、验证命令与结果、未完成项；未执行的检查不得表述为通过。

## 5. 验收口径

- 逐物匹配输出事件，不只看总数：漏 3 件与重 3 件可能互相抵消。
- Precision＝正确事件/全部输出；Recall＝正确事件/全部应计物料；分别记录漏计、重计、方向错误、ID 切换、未解决歧义。
- 基础吞吐先验证 640×400@30；720p60 单独升级。
- 板端结果必须区分本地回归、板端兼容/运行证据与人工真值。

## 6. 本轮执行范围（P1）

- 写本计划并提交到分支。
- P1 基线盘点：候选入口（`scripts/rle`、`scripts/standalone`、G4 候选包、部署配置）、位流/overlay 配置、历史证据边界。
- 委派 `luna_explorer` 只读核对清单与实际代码一致；Manager 复核后提交。
