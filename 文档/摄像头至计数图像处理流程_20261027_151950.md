## Gray8 DMA 计数链（WO-0016）

```text
USB 摄像头（V4L2）请求 MJPG 640×400 @60，实测 ≥50 FPS 才继续
→ capture.read() 原始压缩 MJPEG 字节（校验 SOI = FF D8）
→ cv2.imdecode(IMREAD_GRAYSCALE) 直接解为 640×400 Gray8（256,000 B）
→ 映射为 320×240 Gray8（76,800 B）
   ├─ legacy：cv2.resize(INTER_NEAREST) 拉伸
   ├─ letterbox / 调光配置：source[::2,::2] 等比例抽样 + 上下填黑边
   └─ lighting-calibrated：先在源图 640×360 ROI 内清掉净轮廓 <60 像素的干扰，再抽样，输出 [30,210) 外清零
→ 打包为 GRAY8_PACKET_V1（16 B 头 + 76,800 B 载荷 + 16 B 尾 = 76,832 B）
   └─ 仅调光配置：打包副本再过发送前 LUT；原始 Gray8 保留给预览与取证
→ MM2S DMA 发送 76,832 B
→ PL：Gray8 包适配器逐行发像素 → axis_gray2binary 固定阈值（≥128 → 255）→ 输出 checker
→ S2MM DMA 接收 76,800 B Binary8 掩膜
→ PS：缓存同步 → 整帧回拷 → S2MM／Packer 状态与帧数核对
→ MaskCounter：ROI 校验 → 行/列投影与前景统计 → 8 连通域
→ 面积/框尺寸筛选、粘连拆分与聚类
→ 跨帧关联跟踪
→ 越线判断和累计计数
→ 计数结果、轨迹与运行状态；预览与录像为可选支路
```

1. **采集与协商：**程序按 V4L2 打开相机，请求 `MJPG 640×400 @60`、单帧缓冲（`CAP_PROP_BUFFERSIZE=1`）并强制 `CAP_PROP_CONVERT_RGB=0`，即 `capture.read()` 返回的是原始压缩字节而不是已解码画面。请求后会回读并校验实际格式、分辨率与帧率：格式必须仍是 MJPG、分辨率 640×400、实测 FPS 不低于 50。启动先丢弃 2 帧预热，随后由一个 `wo0016-camera-prefetch` 预取线程提前读下一帧，读超时默认 5 秒且不重试。调光配置额外在相机侧下发并回读曝光/亮度等控件。代码：[采集与协商](../scripts/wo0016/run_stream_counter.py)。
2. **解码：**读到的 `uint8` 压缩包先校验 JPEG SOI 标记（`FF D8`），再用 `cv2.imdecode(..., IMREAD_GRAYSCALE)` 直接解成 640×400、每像素 8 位的 Gray8，即每帧 256,000 字节；形状或 dtype 不符即报错。这条链路不先生成彩色图再转灰度，也没有 RGB 回退。
3. **映射与缩放：**640×400 Gray8（256,000 B）映射为 320×240 Gray8（76,800 B）。`legacy` 走 `cv2.resize(INTER_NEAREST)` 直接拉伸；`letterbox` 与调光配置走 `resize_monochrome_into`：用 `source[::2, ::2]` 做等比例步长抽样（不是插值）写入输出第 20–219 行，上下填黑边。`lighting-calibrated` 先在源图 ROI 行 20–379 内按 `gray > T` 二值化、以 `RETR_CCOMP` 外轮廓面积减子洞面积，把净轮廓面积小于 60 像素的干扰前景清零，再抽样，输出 30–209 行以外清零；`lighting-calibrated-output-roi` 跳过源图这一步，改为在输出 ROI 内做同样的连通域面积门限。调光配置的映射关系为 `x_out=x_source/2; y_out=y_source/2+20`，计数 ROI 取输出行 30–210、计数轴为 x、计数线 `line_x=160`、方向 +1。这些是可选运行配置，并非已冻结的方案。代码：[运行配置与采集](../scripts/wo0016/run_stream_counter.py)、[图像映射](../scripts/wo0016/live_calibration.py)、[面积过滤](../scripts/wo0016/lighting_profile.py)、[参数缩放](../scripts/wo0016/scale_parameters.py)。
4. **打包与发送：**PS 把 320×240 Gray8 封装为 `GRAY8_PACKET_V1`，总长 76,832 字节：16 字节小端头（magic `0x47525938`、`(H<<16)|W`、像素数 76,800、frame ID）+ 76,800 字节载荷 + 16 字节小端尾（magic `0x454E4438`、frame ID、载荷字节求和模 2³²、结束 magic `0xC0DEC018`）。校验是加和校验，不是 CRC。调光配置下，只有即将发送的副本会再过一层发送前 LUT：偏移 `128-(T+1)`（默认 T=100 即 +27，上下饱和截断），因此 `gray=T` 映为 127、`gray=T+1` 映为 128，与 PL 的 `≥128` 判断等价；被清零的黑边行同样经过 LUT，默认值为 27，仍低于阈值，所以不会变成前景。原始 Gray8 不被改写，继续用于预览和取证。
5. **DMA 传输：**DMA 使用两个 TX/RX CMA 槽位对做乒乓，TX 每槽 76,832 字节、RX 每槽 76,800 字节，分配时校验字节数、对齐和物理地址不重叠。每帧先提交 S2MM 接收再启动 MM2S 发送，两者并发等待；S2MM 实际传输长度必须等于 76,800 字节，超时或长度不符即按失败处理。
6. **FPGA 二值化：**PL 侧这条 pipeline 只实例化包适配器、`axis_gray2binary` 和输出 checker 三级，没有例化 ROI、形态学或 CCL 模块。适配器校验包头包尾、几何、像素数与 frame ID 后逐行发出 Gray8；阈值模块对每个像素做无符号比较 `s_tdata >= THRESHOLD`，成立输出 `0xFF`，否则 `0x00`，即相等也算前景；`THRESHOLD` 默认 128，超出 [0,255] 在综合期直接报错。输出 checker 统计像素数、行标记与校验和。代码：[图像 pipeline](../fpga/experimental/gray8/axis_dma_gray_image_pipeline.v)、[阈值模块](../fpga/rtl/axis_gray2binary.v)。
7. **取回掩膜：**S2MM 把 76,800 字节 Binary8 掩膜送回 PS 后，程序先同步缓存，再把接收缓冲整帧回拷到 CPU 掩膜。随后逐帧核对：S2MM 传输长度、DMASR 寄存器、以及 Packer 的 accepted_pixels = 76,800、sent_beats = 76,800/4、error_code = 0、done 置位且未 busy/fault。这组核对在当前板端链路里是每帧执行的，不是只在部分测试中启用。
8. **ROI 与前景统计：**掩膜先按 `uint8 (240,320)` 校验，再在 ROI 内用一次 `inRange(1,254)` 排除既非 0 也非 255 的像素。随后用 `cv2.reduce` 求行投影、列投影和前景总像素数。ROI 有两种：`lane` 取计数线上下各 `roi_half_height` 行的带状区域（legacy 默认 `line_y=120`、半高 24，即第 96–144 行）；`full` 取整段 `roi_top..roi_bottom`（调光配置为 30–210）。只有前景总数达到 `min_area` 才会进入连通域分析，`ccl_executed` 标志会如实记录本次是否执行。代码：[掩膜计数](../scripts/wo0016/stream_counter.py)。
9. **候选区域：**ROI 前景达标后做 8 连通域分析，优先使用 `connectedComponentsWithStatsWithAlgorithm(..., CV_16U, CCL_GRANA)`，不可用时回退到默认实现。每个连通域按面积上下限和包围框宽高上限筛成候选；超出上限的区域记为 rejected/glare 并记录面积。开启 `guarded_merge` 时，面积落在 `(single_intact_area, max_split_area]` 的连通域会调用粘连拆分，要求拆出的 2–3 个连通片完整、可覆盖且互不重叠地解释原区域，否则保留原候选；之后还可按包围框间距、横向/纵向展开和合并跨度上限做一次聚类，质心按面积加权。真实物料的拆分效果仍需验证。
10. **跟踪与计数：**当前帧候选与已有轨迹按方向位移、横向位移、面积比（默认 [0.25,4.0]）和预测距离建立关联；轨迹连续命中 `confirm_hits` 次才确认。轨迹在进入侧越过 `-hysteresis` 边界时 armed，确认后越过正向 `+hysteresis` 边界只计一次；配置了冷却窗口时再按帧数与横向距离抑制重复事件。
11. **输出：**每帧结果包含累计计数、候选、事件、轨迹快照、行/列投影、ROI 边界和 glare 统计。预览与录像都是观察支路：正常板端运行时按每 4 帧一次、JPEG quality 70 向 `/stream.mjpg` 与 `/binary.mjpg` 推送 Gray8 叠加图和 S2MM 二值图；调试快照开关默认关闭，开启后最多每 2 秒取同一帧生成五步对照图；选择性录像可保存输入 Gray8、输出 Binary8 和元数据。

## 独立 RLE / HDMI 相机显示计数候选（G3）

这条 standalone 候选与上面的 320×240 Gray8→Binary8 DMA 链是不同的数据通路。它将 640×400 Gray8 输入送入 RLE DMA；S2MM 返回有界、长度随内容变化的 RLE packet。显示用的 Binary8 是 PS 从 RLE runs 栅格化生成的预览平面，不是 DMA 返回的完整 Binary8 帧。

```text
USB 摄像头 MJPG
→ V4L2 读取并由 OpenCV 直接解码为 640×400 Gray8
→ LatestCamera 后台线程保留最新帧
→ Gray8 packet → MM2S DMA → PL RLE 处理 → S2MM 返回 RLE packet
→ PS 根据 RLE 结果更新候选区域、轨迹与计数
   ├─ 计数状态继续运行
   └─ 显示开启时：RLE runs 栅格化为 640×400 Binary8
      + 同帧 640×400 Gray8 → 绘图子进程合成 1280×720 单通道 Gray8 画布
      → 三槽共享帧 → VideoPump 复制到 CMA 帧并提交 HDMI
```

- **采集与 DMA：**运行器向 V4L2 请求 MJPG 640×400@60，OpenCV 用 `IMREAD_GRAYSCALE` 直接解码到 640×400 Gray8，并丢弃两帧预热图像。每帧 Gray8 有效数据为 256,000 字节，TX packet 为 256,032 字节；S2MM 接收 RLE 数据，接收缓冲上限为 67,744 字节，实际 packet 长度随 runs 数量变化。代码：[相机采集与解码](../scripts/rle/run_counter.py)、[最新帧读取](../scripts/standalone/camera.py)、[RLE 协议与传输](../scripts/rle/protocol.py)、[集成运行器](../scripts/standalone/integrated_run.py)。
- **计数与显示分支：**PS 将返回的 RLE packet 交给 `advance_count` 更新计数状态。显示开启时，同一 packet 的 runs 另行栅格化为 640×400 Binary8，并和输入 Gray8 配对交给绘图子进程；显示关闭或绘图进程不可用时，计数主链可继续运行。
- **HDMI 合成：**画布是 1280×720、单通道 `uint8`。左侧上下各显示 576×360 输入视图（上方 Gray8，下方默认 Binary8；关闭二值背景时下方显示 Gray8），右侧显示状态信息并叠加候选、轨迹及计数线标注。当前候选实现对 Gray8 使用 `INTER_AREA`、对 Binary8 使用 `INTER_NEAREST`；本地像素比较不等同于板端 HDMI 黄金图或可见性验收。代码：[画面合成](../scripts/standalone/compositor.py)、[共享帧](../scripts/standalone/shared_frames.py)、[HDMI 显示泵](../scripts/standalone/video_pump.py)。

## 看板展示与图像调试

2026-10-27 15:46 设计、其后落地的图像调试模式属于观察支路，不改变上面的计数链：

- **图像处理调试模式。**默认关闭；开启后 `DebugSnapshots` 最多每 2 秒取同一帧，按"图像映射→阈值分割→ROI 选择→区域分析→跟踪与计数"五个步骤给出处理前后对照（JPEG，质量 70，仅观察不可逐像素验证）。板端链路调用 `publish_preview` 时把 FPGA S2MM 输出作为分割后画面；相机软件预览则以软件阈值输出为分割后画面、并可提供原始相机帧。区域分析和跟踪计数两步的"处理后"画面是基于实际结果绘制的叠加图（ROI 绿框、候选框与中心点、轨迹 ID 与计数线），不是算法中间图。
- **步骤不可用时的表述。**板端当前预览回调不提供映射前的原始相机帧，页面会显示"原始相机帧未提供"而不是用替代画面冒充；调光校准模式下分割前画面是发送前灰度 LUT 映射之前的 Gray8，并附文字说明。
- **控制与资源监视。**调试开关经 `/api/debug-mode`（仅本地同源 POST）启停，关闭即停止调试图的采集、绘制与编码；资源监视器（`/api/resource-monitor`）可开关并在详细模式下显示 CPU/内存/CMA、DMA 状态及静态 FPGA 资源数据。

## 相机软件预览

[相机软件预览](../scripts/wo0016/camera_only_preview.py) 同样采集、解码和映射相机图像，但使用 OpenCV 在软件中生成二值掩膜，再交给掩膜计数逻辑。它不启用 DMA，其软件二值图不能当作 FPGA 实际输出。默认阈值为 128 时，软件的 `THRESH_BINARY` 对大于 128 的像素输出白色，而 PL 对大于等于 128 的像素输出白色；默认拉伸的实现也不同，映射后的灰度图可能存在逐像素差异。

2026-10-27 已在板上以独立进程恢复该预览（软件阈值、`SIM COUNT` HUD，DMA 与 FPGA 计数关闭）；当前实例的 PID、部署目录与停止方法以 [脚本 README](../scripts/wo0016/README.md) 和 [网页预览验证报告](../data/results/web-preview-20261027-124938/README.md) 为准。它占用 `/dev/video0` 与 8080 端口，后续 DMA/计数测试前须先停止。
