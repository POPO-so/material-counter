# 摄像头至计数图像处理流程

- 整理时间：2026-10-27 15:19:50（北京时间，UTC+8）
- 更新：2026-10-28 00:41:31（北京时间，UTC+8）。依据当前代码（含提交 9d5e1aa 与其后未提交的预览调试改动）和 2026-10-27 相机板测、网页预览记录核对。
- 范围：当前 Gray8 板端计数链、相机软件预览，以及看板的图像调试与二值图展示。各运行配置可能启用不同的可选步骤。

## 板端计数链

```text
摄像头拍摄
→ MJPEG 数据
→ 解码为 640×400 Gray8 灰度图
→ 映射／缩放为 320×240 Gray8
→ 打包（调光配置下含发送前灰度 LUT 映射）
→ MM2S DMA
→ FPGA 阈值二值化
→ S2MM DMA
→ 320×240 Binary8 掩膜
→ ROI 选择和前景统计
→ 连通域提取、筛选与候选处理
→ 跨帧跟踪
→ 越线判断和累计计数
→ 状态、计数与预览输出
```

1. **采集：**摄像头输出 MJPG 640×400@60，程序读取原始压缩字节并校验 JPEG SOI 标记。采集可包含预热，并可记录帧时间与采集耗时。代码：[相机采集](../scripts/wo0016/run_stream_counter.py)。
2. **解码：**在 PS 上将 MJPEG 直接以 `IMREAD_GRAYSCALE` 解码为 640×400、每像素 8 位的 Gray8 灰度图（提交 c358e18 起）。当前链路不先生成彩色图再转灰度。
3. **映射与缩放：**将灰度图变成 320×240。默认 `legacy` 配置使用 `INTER_NEAREST` 拉伸；`letterbox` 与调光配置使用等比例行/列抽样并填黑边；`lighting-calibrated` 先在源图上做面积过滤（净连通域小于 60 像素的干扰清零、ROI 外的行清零）；`lighting-calibrated-output-roi` 将该过滤移到输出 ROI。调光配置的有效输出行为 30–210 行。这些是可选运行配置，并非已冻结的方案。代码：[运行配置与采集](../scripts/wo0016/run_stream_counter.py)、[图像映射](../scripts/wo0016/live_calibration.py)、[面积过滤](../scripts/wo0016/lighting_profile.py)。
4. **打包与发送：**PS 将 Gray8 图像封装为 GRAY8_PACKET_V1 数据包，由 MM2S DMA 送入 PL。320×240 输入每帧数据包为 76,832 字节。调光配置下打包编码器内置发送前灰度 LUT：偏移 `128-(T+1)`（默认 T=100 即 +27，带饱和截断），黑边行同样经过 LUT；因此 PL 看到的输入灰度已被搬移，等价于按 T 的软阈值、PL 阈值仍固定 128。代码：[LUT 与打包](../scripts/wo0016/lighting_profile.py)、[包编码器](../scripts/wo0016/packet_encoder.py)。
5. **FPGA 二值化：**PL 对每个灰度像素按固定阈值比较，大于等于 128 输出 255（白），否则 0（黑）；RTL 参数 THRESHOLD 默认 128，越界即综合期报错。调光映射配置会影响输入灰度与有效阈值的对应关系（见第 4 步）。代码：[阈值模块](../fpga/rtl/axis_gray2binary.v)。
6. **取回掩膜：**S2MM DMA 将 320×240 Binary8 掩膜送回 PS，每帧 76,800 字节；程序同步并复制输出缓冲区。部分板测会逐像素核对输出与软件期望值；这属于验证，不是每次运行必然启用的处理步骤。
7. **ROI 与前景统计：**在掩膜中选取计数区域，检查 ROI 的像素值，并统计前景像素、行投影和列投影。ROI 可按配置使用完整区域或计数线附近的带状区域。代码：[掩膜计数](../scripts/wo0016/stream_counter.py)。
8. **候选区域：**ROI 前景像素总数达到配置的最小面积后，才执行 8 连通域分析，得到面积、位置和中心等信息，再按面积、框尺寸等筛选，并根据配置聚类或处理粘连候选。真实物料的拆分效果仍需验证。
9. **跟踪与计数：**将当前帧候选与已有轨迹关联；目标满足确认、方向和越线等条件后，产生计数事件并更新累计数量。
10. **输出：**计数、轨迹和运行状态可用于预览或记录。部分运行支持选择性保存输入 Gray8、输出 Binary8 和元数据；预览是观察结果的支路。

## 看板展示与图像调试

2026-10-27 15:46 设计、其后落地的图像调试模式属于观察支路，不改变上面的计数链：

- **主画面与二值图分列。**看板主画面显示叠加跟踪 HUD 的 Gray8 相机画面，不再叠加二值画中画；二值掩膜经同一处理帧以 JPEG 单独编码，经 `/binary.mjpg` 独立推送。二值流来源按运行模式标注（FPGA S2MM 输出或软件阈值输出）。两条图像流同帧生成；暂停预览会同时停止两条流，不影响采集和计数。
- **图像处理调试模式。**默认关闭；开启后 `DebugSnapshots` 最多每 2 秒取同一帧，按"图像映射→阈值分割→ROI 选择→区域分析→跟踪与计数"五个步骤给出处理前后对照（JPEG，质量 70，仅观察不可逐像素验证）。板端链路调用 `publish_preview` 时把 FPGA S2MM 输出作为分割后画面；相机软件预览则以软件阈值输出为分割后画面、并可提供原始相机帧。区域分析和跟踪计数两步的"处理后"画面是基于实际结果绘制的叠加图（ROI 绿框、候选框与中心点、轨迹 ID 与计数线），不是算法中间图。
- **步骤不可用时的表述。**板端当前预览回调不提供映射前的原始相机帧，页面会显示"原始相机帧未提供"而不是用替代画面冒充；调光校准模式下分割前画面是发送前灰度 LUT 映射之前的 Gray8，并附文字说明。
- **控制与资源监视。**调试开关经 `/api/debug-mode`（仅本地同源 POST）启停，关闭即停止调试图的采集、绘制与编码；资源监视器（`/api/resource-monitor`）可开关并在详细模式下显示 CPU/内存/CMA、DMA 状态及静态 FPGA 资源数据。
- **本机网页入口。**Windows 侧 `Python脚本/启动网页.cmd` 一键完成板端自检与预览启动、本机 18765 回环代理（看板页面、状态、两条图像流和调试接口）及"后端代码更新"部署；页面带版本指纹，代码变化时自动刷新。

代码：[调试快照](../scripts/wo0016/image_debug.py)、[预览服务](../scripts/wo0016/mjpeg_preview.py)、[看板页面](../scripts/wo0016/dashboard.html)、[资源监视](../scripts/wo0016/resource_monitor.py)、[Windows 启动入口](../Python脚本/启动网页.cmd)。

## 相机软件预览

[相机软件预览](../scripts/wo0016/camera_only_preview.py) 同样采集、解码和映射相机图像，但使用 OpenCV 在软件中生成二值掩膜，再交给掩膜计数逻辑。它不启用 DMA，其软件二值图不能当作 FPGA 实际输出。默认阈值为 128 时，软件的 `THRESH_BINARY` 对大于 128 的像素输出白色，而 PL 对大于等于 128 的像素输出白色；默认拉伸的实现也不同，映射后的灰度图可能存在逐像素差异。

2026-10-27 已在板上以独立进程恢复该预览（软件阈值、`SIM COUNT` HUD，DMA 与 FPGA 计数关闭）；当前实例的 PID、部署目录与停止方法以 [脚本 README](../scripts/wo0016/README.md) 和 [网页预览验证报告](../data/results/web-preview-20261027-124938/README.md) 为准。它占用 `/dev/video0` 与 8080 端口，后续 DMA/计数测试前须先停止。

## 边界与验证状态

- 独立验证过的 ROI 和形态学 RTL 模块尚未全部接入当前板端数据通路，不能默认将腐蚀、膨胀等列为每帧必经步骤。
- 2026-10-27 相机板测使用 `lighting-calibrated` 配置；3 帧合成输入和 960 帧相机输入均通过全像素比对。三轮各 300 帧的加权处理速率为 19.5448 FPS，包含启动／预热、逐帧校验和 PS 计数。相机掩膜全黑，不能据此证明真实物料识别、计数准确率或复杂画面吞吐。参见 [相机板测记录](../data/results/gray8-camera-20261027-122633/README.md)。
- 图像调试模式与独立二值图流增加了 JPEG 编码和传输开销；实际板端开销尚未测量，也不构成 FPGA 行为或物料识别验证。
- 打包、DMA 同步、轨迹关联和计数事件等步骤主要产生数据或状态，未必各自有一张天然的处理后图像；调试页面通过叠加标注和数值信息呈现。
