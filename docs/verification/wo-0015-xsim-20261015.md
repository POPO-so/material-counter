## 只读 RTL 最终审查

按当前工作区源码复核 packer、wrapper 与输出 checker 的计数和握手路径：

- [axis_s2mm_frame_packer.v](../../fpga/experimental/wo0015/axis_s2mm_frame_packer.v)（第 14–39、46–105 行）以 `PIXELS=WIDTH*HEIGHT`、`BEATS=PIXELS/4` 约束满 32-bit 输出几何，并通过 generate 分支的 `initial $fatal` 拒绝非法几何。`accepted_pixels` 对应经 SOF/EOL/二值检查后接受的输入像素；`sent_beats` 只在 `m_tvalid && m_tready` 外部输出握手时递增。两者随 reset 清零，并在 arm 时按帧清零。
- Wrapper [axis_dma_s2mm_pipeline_bd.v](../../fpga/experimental/wo0015/axis_dma_s2mm_pipeline_bd.v)（第 119–155、211–232、272–297 行）把 `0x50/0x54` 映射到 packer 的上述每帧计数。旧诊断寄存器如输入 beat/byte、packet 完成计数、`accepted_output_total` 和停顿周期则在复位时清零并持续累计；其中 `0x44` 统计 binary pipeline 到 packer 的接受拍，`0x48` 统计该级 `TVALID && !TREADY` 周期，不等同于外部 DMA 已接收的 `sent_beats`。
- 输出停顿时，packer 的 `out_space` 拉低 `s_tready`，阻止新输入覆盖输出槽；只有 `out_fire` 才清除 `m_tvalid`。`m_tdata/m_tlast/m_tvalid` 在 `TVALID && !TREADY` 期间没有撤拍或改写路径，packet fault 也不会撤回已呈现的输出拍；同步 reset 会清零 valid。pipeline TB 在前一拍停顿后逐项断言 `TDATA/TKEEP/TLAST/TVALID` 稳定，相关 XSim 回归通过。
- 末输出字保存在 `final_word`，`final_pending` 期间不对外呈现。只有 packet adapter 的 `packet_done` 已到（或已锁存为 `packet_ok`）、无 `packet_error` 且输出槽可用时，才检查像素数、lane 和 beat 数并发出带 `TLAST` 的末拍。小几何 packer XSim 覆盖 packet_done 早到、晚到以及末拍停顿；均通过。
- checker 与 packer 共用 binary pipeline 的接受握手点。Wrapper 的 `pipe_m_tready = drain_enable && packer_ready`，packer 输入 valid 为 `pipe_m_tvalid && drain_enable`；wrapper 的 `output_fire`、packer 的 `in_fire` 与 [axis_binary_output_checker.v](../../fpga/experimental/wo0014/axis_binary_output_checker.v) 的 `beat_fire` 因而是同一组 `pipe_m_tvalid && pipe_m_tready` 条件。checker 只在该握手上更新像素、SOF、EOL 和 checksum；它不等待 packet_done，因此覆盖每个被 packer 接受的 Binary8 字节。外部 `sent_beats` 则单独按 DMA 输出握手计数。

本次只读复核没有确认上述路径存在阻塞缺陷。结论限于检查过的源码路径和已记录的 XSim 用例；这些证据不代表综合、实现/时序或板端 DMA 验证。
