| 同色完全接触 | 仍是一块区域，不能凭标签数找回物体 | 同样无解，宽区域仅标疑似合并 | 当前也漏12，不声称软件可凭空恢复 |
| 难度/工作量 | 高，超当前Scope边界/工期；无生产实现 | 中，需要行调度/缓存/RMW/除法/异常黄金 | PC已运行；PS依赖/驱动/实际耗时未验证 |
| RAM | 一种整帧16位标签图仅本体150KiB，另需等价表/矩/输出；流式CCL可用其他存储，但控制复杂度仍需证据 | 不存标签整帧，逻辑状态约2080B；宽口映射5～7 BRAM36为假设 | Binary包76816B，双缓冲153632B有效字节，DDR分配对齐另计 |
| 时序 | 等价合并/冲突/指针访问风险大 | 固定限值、串行调度；RAM访问拍数与同ID累加是关键 | PL适配较简单；PS调度、cache和DMA吞吐未知 |

## 4. 候选有界设计与容量来源

每行收集前景run，与上一行run用±1区间相交判断8连接。
无前驱出生；一前驱ID继承；同ID可分叉再汇合；不同ID汇合整帧拒收，不用union-find。
先识别继续出现的旧ID，关闭无后继旧ID，再分配新ID，避免相邻两行20旧/20新造成无谓40槽峰值。
EOF关全部剩余对象，面积/bbox/整数矩只对每个run计一次；末列/末行/触边不丢像素。
输出按关闭顺序，不付出硬件x排序成本。

| 项 | 实测/推导 | 推荐草案 |
|---|---|---|
| 最大物料数量 | H3每帧20身份，图像最多20区域；不是实物密度上限 | 示范包线先按20同时对象准备，真实H5待确认 |
| 活动标签 | H3峰值20；20带孔算例同为20 | ACTIVE_CAP32=nextpow2(20) |
| 输出记录 | H3峰值20 | RECORD_CAP32=nextpow2(20)，输出32不是64物体承诺 |
| 行run | H3旁路/腐蚀/膨胀峰值都20；独立20孔目标峰值40 | 物理64槽/行=nextpow2(40)，运行限制先40；64运行另评估 |
| 面积 | 分离H3 112，腐蚀72；原最大区域2240 | min16为当前参考默认待标定；最大65535是B字段边界，内部17位防回绕 |
| bbox | 软件包含端点全帧坐标 | x10/row8，限定320×240；不直接承诺640×480 |
| 质心 | 精确sum/area | 最近整数、半值向上，误差≤0.5；审批后建立同策略黄金 |
| 异常 | 多根形状/噪点/容量/面积/坏标志 | 不截断、不部分交付；错误帧metadata+PS拒收 |
| PS接收 | 现有软件Region入口 | S2MM完整包→同步/长度/epoch/ID/范围校验→Region→现有Tracker；不读GT |

行运行限制40来自明确的20个单孔算例，不是H3实测40，也不是保证所有真实螺母最多2run。
实际准入按总行run≤40、活动≤32、完成记录≤32；单对象可有更多分枝，只要总量及单根条件满足。
原始噪点会先耗run/槽，不能用min_area提前假装消除容量风险。
U形两个上端分别出生、之后汇合也会拒收，即使它物理上只有一个物体；真实拒收率必须测。
从帧首已相接的多个物体可能只出生一个ID，不必触发多根错误，宽度标志也未必查出全部粘连。

## 6. 精度与越线

`wo0012_protocol.py`在全21序列/同line160/h2协议比较真实字节编解码后的特征：

| 质心方案 | TP/FN | duplicate / 其他FP | ID switch | 精确率 / 召回率 |
|---|---|---|---:|---|
| float原参考 | 19/12 | 0/0 | 0 | 100% / 61.29% |
| floor整数 | 5/26 | 0/14（错时） | 0 | 26.32% / 16.13% |
| nearest half-up整数 | 19/12 | 0/0 | 0 | 100% / 61.29% |
| 有界run→关闭顺序打包→nearest解码→Tracker | 19/12 | 0/0 | 0 | 100% / 61.29% |

两整数方案本批每轴最大误差都0.5；误差幅度相同但舍入偏置与迟滞条件不同，事件结果不能只由max error判断。
H3整半像素质心和较早armed提供了特殊条件，不能外推真实形状。
补充特征序列x=154,156,162.2,163证明nearest也可从原第2帧事件延迟到第3帧，总数虽相等但严格协议不合格。
位置差误差最多1px，速度估计误差也可传播预测；小间距/漏帧后可能改变关联排序。
这里H3 ID switch0不等于普遍保证；bbox/area/整数矩要求完全一致，wire质心按已批准整数黄金比对，
最终真实计数仍用独立原事件GT，不放宽协议掩盖量化损失。
浮点sum/area不直接塞10/8位，不能利用H3矩形bbox中点作为任意物体质心替代。
最终串联结果在 `data/results/wo0012-integration-acceptance-20261013/`：全部21序列含17缺帧，
有界模型0拒帧，期望epoch/ID均核验；关闭顺序的输入没有增加H3关联/计数损失。
此codec仅实现二维候选，不是假装交付Route A解析。

## 7. 资源与吞吐预算（不是综合/时序结果）

内部area17、sum_x/sum_y25：保守上界分别76800、24499200、18355200，均不会因完整帧静默回绕。
run32位×64×2行=4096bit；活动128位×32=4096bit；输出128位×32×2槽=8192bit；帧尾128位×2=256bit。
合计16640bit=2080B逻辑状态，另需计数/bitmap/控制寄存器/可选FIFO。128位活动槽用于bbox/矩/有效状态，不是输出记录本身。
RAMB36 SDP口宽最多72，宽128表不能简单按总bit除36Kb：候选宽口映射与小FIFO约5～7个BRAM36等价块。
这是假设，实际可能用LUTRAM/更多BRAM，依推断与端口调度而变；LUT/FF目前不给伪造使用数。
共享run矩乘法预计0～1个DSP，须综合核实；串行除法避免32个并行除法器，但增加尾部等待。
器件53200 LUT/106400 FF/140 BRAM36/220 DSP可由旧utilization可用栏及
[AMD DS190](https://docs.amd.com/v/u/en-US/ds190-Zynq-7000-Overview)核对，
端口映射见 [AMD RAMB36E1](https://docs.amd.com/r/2025.2-English/ug953-vivado-7series-libraries/RAMB36E1)。
新核未综合，不能把这些可用总量或旧Morph的低占用当作完整设计剩余资源或时序通过。

若以串行pair比较2或4拍、每run统计6拍、每新根最多扫描32槽、每行关闭扫描32槽、
每轴除法含round27拍、AXIS32每记录/帧尾4拍、100MHz且无DMA stall为**预算假设**：

| 运行行run限值 | pair2拍 | pair4拍 |
|---|---:|---:|
| 40 | 约13.12ms/帧 | 约20.80ms/帧 |
| 64 | 约25.44ms/帧 | 约45.10ms/帧 |

表内已将现有Morph 153840拍完全串行相加以不依赖重叠；它不是周期精确仿真，也不是最坏上界证明。
64情况下pair只多两拍就超30fps的33.33ms预算，因此不先扩大运行限值。
BRAM RAW同slot更新、共享乘法/除法、mode/epoch同步、reset/排空和输出stall均待实际握手与实现测量。
数学算例和公式在 `data/results/wo0012-design-budget-20261013/budget.json`，旧Morph拍数来自WO9 XSim，非本轮重测。

20条特征336B@30fps=10080B/s；32条最大528B@30fps=15840B/s；Binary debug76816B@30fps≈2.30448MB/s。
这些只是有效负载预算，不是实测DDR/DMA/PS性能。数据包小仍可能因IRQ/软件调度阻塞。
不可暂停源FIFO需求至少满足 `sup_t(arrivals(t)-service(t))`，必须覆盖源突发/消隐、全部row stall与DMA延迟。
单次stall乘像素率只是局部下界，不能把它当整帧FIFO充分容量；源未定不选一个假定深度。
