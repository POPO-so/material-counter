# 仪表盘渲染优化设计

日期：2026-11-02

## 目标

按顺序降低 `DashboardComposer` 的面板重建频率，再减少每帧不必要的静态面板绘制与复制。保持输出 1280×720、计数与跟踪输入、相机预览、按钮行为、PL/HDMI 接口不变；不部署板端。

## 依据与现状

- 当前工作流由 `integrated_run.drawing_process()` 创建 `DashboardComposer`，绘制结果写入三槽 `SharedFrames` 输出池。
- 面板 key 混用最终显示字符串和原始浮点数。CPU、内存、FPS、RLE 等值即使舍入后显示相同，原始值变化仍会触发整张 chrome 重建。
- 画布为 1280×720；相机预览和帧身份标记每帧变化，顶部/侧栏/资源面板按 dashboard key 更新。
- CPU/帧率等数据沿用现有低频遥测采样；本任务不改变采样周期。
- 没有现场面板字段访问率数据。保留计数、吞吐、丢帧、CPU/内存、PL/RLE 和控制状态；把 CPU 来源、队列及线程诊断收至 PS/丢帧详情页。

## 方案

1. 让面板缓存 key 只表达屏幕可见值：浮点数按显示的一位小数归一化，整数/状态/未知值保持原有表示；绘制也消费同一归一化值，确保 key 命中代表面板像素无需更新。面板详情使用现有 BTN3 页面数据。增加有界整数计数器，记录绘制帧数、key 命中/重建次数和命中率。
2. 保留面板 chrome 作为持久静态图层。将输出共享槽位编号传给绘图器，并为三个输出槽分别记录 chrome 版本。key 未变时不把整张 chrome 复制到输出槽；key 变化时仅在该槽下次复用时同步新版 chrome。每帧仍完整覆盖相机预览区域、该帧会绘制的叠加层和两行帧身份标记；PL 预览模式的现有清屏语义保持不变。没有槽位编号的独立调用走安全的完整同步路径。

输出槽首次使用、面板版本变化、槽位复用和详情页切换都必须保持完整 1280×720 像素有效。VideoPump 的全帧拷贝不变；优化只减少绘制和冗余静态复制。

## 验收

- 第一步用确定性动态遥测序列验证显示精度内的微小变化命中 key、显示精度跨界触发重建、关键字段仍可见；记录 100 帧以上的 key 命中率和 `draw_ms`。
- 第二步用多个共享输出槽、槽位复用、静态 key 更新及动态帧对照全量渲染结果；普通二值预览、PL 预览、标记/CRC 与计数输入均保持正确。
- 每阶段运行对应 `scripts/standalone/test_compositor.py` 测试，并用相同本地合成帧工作负载记录 `draw_ms`。本地结果不作为板端实测或 300–600 ms 板端目标的证明。
- 仅在分阶段本地验证后提交；不改 1280×720、不改计数/阈值/跟踪/控制逻辑、不部署或重启。
