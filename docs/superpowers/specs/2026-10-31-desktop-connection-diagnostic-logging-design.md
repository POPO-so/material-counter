# 桌面 GUI 连接与首帧诊断日志设计

日期：2026-10-31

## 意图

让一次真实物料观察会话能从日志中分辨 SSH 登录、文件部署、板端进程启动、HTTP 会话校验和首帧传输分别停在哪一步。2026-10-31 的只读检查已确认 SSH 认证成功、板端 8080 服务可达，当前 RLE 会话通过有效令牌返回 HTTP 200 且已处理 663 帧；无令牌请求返回预期的 403。当前证据说明 GUI 的连接提示可能没有指出失败层级，具体关联仍需带会话号的日志确认。

## 目标与边界

- 在现有本机 `.runtime/desktop-gui.log` 中记录 GUI PID、会话 ID、板卡地址/端口、阶段、结果和耗时；覆盖 SSH、SFTP 部署、板端启动、HTTP 就绪检查、远端失败结果、首帧、图像重连和停止。
- 在板端每会话 `viewer.log` 中记录锁获取、自检、相机打开、首帧、HTTP 服务就绪、低频运行心跳、异常和清理结果，并用会话 ID 对应本机日志。
- 记录 HTTP 状态码以及预期与实际会话 ID，帮助区分拒绝连接、未授权和其他会话占用端口的情况。
- 日志不得包含密码、Bearer token、SSH 私钥、认证头或图像/帧内容。运行心跳限频，不逐帧写日志。
- 本任务只增加诊断信息；不改变自动启动、进程优先级、连接重试、单实例/板端所有权、相机/DMA 操作、计数算法或现有协议。修改后的板端日志在该版本服务下次部署启动后生效，不热插入正在运行的会话。

## 方案

1. **只增加本机 GUI 日志：** 改动较小，可确认客户端发起了哪些连接步骤；板端自检、相机和首帧仍需依赖现有 `viewer.log` 内容判断。
2. **本机 GUI 与板端会话日志（选定）：** 本机记录连接和 HTTP 会话校验；板端在已有 `viewer.log` 中记录启动阶段、首帧、限频运行状态及退出/异常。两端共享 session ID，能覆盖 SSH 已成功但服务尚未回帧的故障路径；增加的日志仅在新代码启动的会话中生效。

## 实施范围与验收

- 主要代码范围：`scripts/desktop_gui/controller.py`、`scripts/desktop_gui/board_entry.py`、`scripts/desktop_gui/rle_desktop_board.py`；针对当前配置的 `RLE_PACKET_V1` 路径补齐板端帧阶段信息。
- 保持日志可读、低频且脱敏；同一事件至少包含稳定事件名、session ID（若已创建）、PID/板端阶段、耗时或结果。HTTP 事件记录状态码及会话匹配结果，不记录令牌。
- 用本机单元/模拟测试验证阶段日志、会话关联、HTTP 状态区分和秘密字段脱敏，并运行桌面 GUI 相关既有回归。只做离线验证；不因验证而连接、重启、部署或停止当前板端任务。
- 验收时能据一组本机日志和 `viewer.log` 判断失败发生在 SSH、SFTP、板端准入/相机、HTTP 令牌/会话或首帧阶段；不以日志本身宣称物料计数准确。
