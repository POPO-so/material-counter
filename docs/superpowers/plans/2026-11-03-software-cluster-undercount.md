# 软件粘连漏计修复实施计划

> **执行说明：** 按依赖顺序实施；每个阶段先补回归用例，再实现并运行对应定向检查。只有离线门禁通过后才进入板端 FAST 验证，不改 bitstream。

**目标：** 在目标运行工作包线内减少螺母接触、密集粘连及越过计数线后分离造成的漏计，逐件计数且不重复。

**方案：** 在有界父区域内识别并拆分 2–16 个可见环形子物料；扩大 RLE 候选区的拆分机会，使面积超限父块先拆分再拒绝；对短时未能拆分、但被连续观测到越线的父团建立有限寿命归属，只有稳定子轨迹能被唯一关联时才补计。无法可靠判断的样本保留为歧义，不猜测数量。

**技术栈：** Python、NumPy、OpenCV、RLE 区域分析、现有 `MaskCounter`、pytest、板端 PYNQ-Z2。

**设计：** [软件粘连漏计设计](../specs/2026-11-03-software-cluster-undercount-design.md)

## 全局约束

- 保持 `FrameResult`、`Detection`、`CountEvent` 和 UI / PL 契约不变；只允许扩展内部快照诊断，并对新增字段版本化。
- 仅修改 ARM PS 上的 RLE 拆分、字段配置、跟踪归属和对应测试；不改 RTL、bitstream、视频路线、运行时依赖或公开控制接口。
- 原始 `raw_detections` 与最终 `detections` 的统计含义不变；仍记录拒绝区域。成功拆出的子块进入原始候选集合，失败的大团不伪装成一个普通物料。
- 初始硬上限：每个父块最多分析 16 个种子、8192 个前景像素、65536 个父框像素。测试和板端负载必须测峰值内存与区域耗时；标注样本若超出上限，先交 Manager 复核范围，不得临时无界放宽。
- 父团补计必须有可确认的上游越线记录、稳定子轨迹及唯一空间/时间关联；关联冲突、父团未从上游观测到或状态超时均不改变既有线后新轨迹抑制规则。
- 严重堆叠、完全遮挡、无法从图像证据恢复的数量继续标为歧义，不纳入自动猜数范围。
- 真实验收图像必须来自传送带上螺母的连续运行；设备结构照片和合成图只能用于单元测试，不能替代物料真值。
- 只在本任务 worktree 修改、暂存和提交文件；不触碰其他 worktree 或根工作区已有未提交文件。板端验证用 FAST，只更新本次 PS 文件，不重载 PL、不重启整板。

## 重点审查

- 4 个以上环孔种子时，每个输出子掩膜仍 8 连通；所有子掩膜恰好覆盖父掩膜且无重叠。
- 每个子块都落在用单件标注校准的面积和形状范围；小噪声孔、边界孔、遮挡导致的不完整孔心不能诱发拆分。
- 面积超过当前 `max_area=3600` 的目标父块在拆分尝试前不被提前丢弃；拒绝与成功拆分的诊断原因可区分。
- 父团只在越线前已被连续观测并可靠关联时开放子轨迹补计；普通线后新轨迹仍不计数。
- 若父团由 3 件构成，其中 1 件已由独立轨迹计数，分离后最多补计其余 2 件；重复子检测不得再次计数。
- 活跃父团数量、每个父团寿命、子轨迹缓存及像素工作区均有上限；超限转为歧义并回收状态。
- 用同一段逐件标注的 100 件物料视频比较基线和候选：候选总计数 100、无重复事件，逐件漏计为 0，目标片段无未解释歧义；处理速率不低于输入速率且队列有界。
